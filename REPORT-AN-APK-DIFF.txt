R866 - WHY THE TOTAL DID NOT MOVE (measured; every term from the archives)
--------------------------------------------------------------------------------
Every byte of these archives is a local header (30 + name), a local extra
field, entry data, the central directory (9 250 B) or the EOCD (22 B). No
gap and no data descriptor exists. The only padding is in local extra
fields, as raw zero bytes (not extra-field records): 4-byte alignment for
the stored baseline.prof, baseline.profm and resources.arsc, and 16 KiB for
the four stored lib/*.so.

The ledger (android/scripts/apk-diff.mjs, LEDGER section) - delta = header +
padding + data per entry, + central directory + EOCD + gaps:
  PAIR 1  baseline.prof data +7; baseline.profm padding +1 (its start moved
          7 B, re-aligned 2 -> 3); classes.dex data -51; arm64 .so padding
          +43. CD 0, EOCD 0, gaps 0. Sum 0 = measured 0.
  PAIR 2  baseline.prof data -936; baseline.profm data -1 (padding stays 3);
          classes.dex data +1 145; arm64 .so padding -208. CD 0, EOCD 0,
          gaps 0. Sum 0 = measured 0.
  PAIR 3  classes.dex data -2; arm64 .so padding +2. Sum 0 = measured 0.
The arm64 .so's data starts at 1 572 864 in every APK, so the prefix up to
that page boundary is a constant 1 572 864 B whatever it contains. After the
boundary, nothing moved: the other three .so, assets, res/, resources.arsc
and the central directory (fixed-size fields; the same names) are
byte-for-byte where they were. Hence 1 989 388 B five times.

THE SLACK (derived from the rule above, not from a build): with padding p
before a 16 KiB-aligned entry, the content stored before it can grow by up
to p bytes, or shrink by up to 16 383 - p, before the total moves by one
page. Before -> after:
  52da740  p = 4 446
  0616b4e  p = 4 489
  9a6dd55  p = 4 281
  cf485c4  p = 4 283: growth up to +4 283 B, shrinkage up to -12 100 B
Any APK-size check of this app is therefore blind to a dex change smaller
than that slack. Entries stored after the libraries (assets, res/,
resources.arsc) move the size directly, apart from resources.arsc's 0-3 B
of 4-byte padding.

R867 - EVERY DIFFERENCE BY A COMMIT
--------------------------------------------------------------------------------
HOW A ROW IS TIED (the rule, stated once). A difference is tied when the
input that changed is MEASURED and touches the same dex object as the
difference. A tie names the source file and every commit in the pair's range
that touched it. Where several commits touched one file, which of them made
the byte is NOT separable without per-commit builds, and the tie says so by
listing them all. "R8 decided differently" with no changed input shown is
UNEXPLAINED. A mechanism inside R8 or the Compose compiler is labelled a
HYPOTHESIS unless a number confirms it.

APK-SOURCE FILES are those under android/app/src/main and
android/shared/src/{commonMain,androidMain}, matched by package path and
file name. Tests and iOS sets never reach the APK. Commits that touched none
of them, each checked with git show --name-only, have no difference to own:
  pair 1  9ea742f (app/test), 9b9ec0b (app/test, shared/iosTest),
          0616b4e (shared/iosTest)
  pair 2  c37c84c, 7422a78, 9a6dd55 (shared/iosTest)
11f23b7 (pair 2) touched APK sources, but no measured difference lands in a
file it touched. Its moves compiled to the same bytecode, by the measures
used here.

THE CATEGORIES, by strength. Each was computed by the one-off scripts in
.apk-diff-evidence (dexclassdiff.mjs, attribute.mjs), which work in original
names.

  TIER 1 - direct:
  OWN-SOURCE           The member's original owner is in a changed file.
                       For a member R8 merged into a host class, that is
                       its recorded original class.
  FRAME-FROM-CHANGED   The mapping's frames at the differing instructions'
                       pcs lie in a changed file. This covers inlined and
                       merged code.
  CONTRIBUTOR-CHANGED / GROUP-MEMBERSHIP-CHANGED
                       An R8 merged group (synthetic lambdas told apart by
                       an int class id) gained or lost a contributor from a
                       changed file. The contributors are measured from the
                       mapping block on each side.
  LAMBDA-CLASS-ID      A constant that changed is the class id handed to a
                       merged group's constructor (new-instance, const,
                       invoke-direct <init>), and that group's contributors
                       changed as above.
  NAMES-ONLY           Code identical; only the mapping-recorded synthetic
                       name differs. The owner is in a changed file.

  TIER 2 - one measured step removed:
  REFERENCES-CHANGED   The differing instructions name a class whose file
                       changed: a call into, or a field of, changed code.
  CALL-SITES-CHANGED   For a member present on one side only, or for a call
                       target or inlined callee present on one side only,
                       the set of call sites differs between the sides, and
                       the added or removed sites' frames lie in a changed
                       file. For example, R8 keeps a parameter because a
                       new caller passes a different value.

The differing instructions come from an IN-ORDER diff of the methods with
addresses, registers and branch targets masked. One inserted instruction
therefore does not make every later line count as "differing".

EARNS ITS PLACE: android/scripts/apk-diff.mjs (commit f171564), with its
usage in its header:
    node android/scripts/apk-diff.mjs <before.apk> <after.apk> [--all]
It answers, before a release, the question this task exists for: what moved
inside the APK when its size did not. It uses Node built-ins only, is
read-only, and adds no dependency. It prints:
  - every moved entry, with all of its zip fields;
  - the LEDGER, whose terms are summed and checked against the measured
    delta;
  - the padded entries' slack;
  - each moved dex's map_list sections, R8 marker and, at equal length, its
    differing byte ranges named by section;
  - the decoded baseline.prof/.profm, with the embedded dex checksum checked
    against the dex entry's CRC and the bitmap alignment;
  - the signing state.

"NOT EQUAL" for classes2.dex and later lines. This app is single-dex.
