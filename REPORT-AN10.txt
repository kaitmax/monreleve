--------------------------------------------------------------------------------
THE MONTH (increment 1)
--------------------------------------------------------------------------------
calendar/CalendarModel.kt is the pure month model - no Android, no clock, no
network. It turns the device's Room rows into one month's grid. R28: "today" is
supplied as the Paris day string (the controller derives it via todayInParis); the
model never touches a clock, so the month is identical whatever timezone the device
is set to. CalendarControllerTest asserts this directly: a clock at 22:30 UTC on
15 June yields a Paris "today" of the 16th (day 16 isToday, day 15 not), which a
UTC device would get wrong.

The grid is AN3's DayCells, Monday-first (L M M J V S D), leading blanks aligning
day 1 to its weekday. Navigation is a chevron each side, bounded to the tax year
and narrowed to the engine's period for a partial year: firstNavMonth is the
activity start month (or January), and a mid-year start opens the calendar on that
month with the previous chevron disabled (asserted). The kind legend
(DayKindLegend) sits under the grid (R119), and a four-count summary (Suisse,
Domicile, Mission, Non renseigne) reads the kind names from LegendCopy's one home
(R206), never a second copy. The bottom nav (AppBottomBar) shows only the two
screens that exist (R85/R282); Releve and Parametres join it in AN11/AN12.

DayCell (design/) gained three states the calendar needs, each defaulted so no
existing caller or baseline changed: RecordQuality.PENDING (a lettered cell with no
bar - the quality is not yet a server fact, R216), isToday (the FD6 info-soft fill
+ brand number, via tokens, never a raw 2 dp outline which has no token), and
provenance in the a11y announcement (SPEC 8). New baselines: dayCellPending,
dayCellToday, calendrierMonth - all looked at (R184).

THE EDIT SHEET (increment 2)
--------------------------------------------------------------------------------
Tapping a recordable day opens a ModalBottomSheet (24 dp top corners) whose content
is CalendarEditSheetContent: the day title (formatDayLong, French weekday + month
from a PINNED locale, never the device's), the kind chooser reusing Aujourd'hui's
vocabulary (En Suisse / Domicile / Mission -> En France / Pays tiers / Declarer une
absence -> reasons), a note field, and Enregistrer / Annuler.

D16: nothing is written until the Save tap. The rows only change local selection;
onSave records through the SAME EntryRepository Aujourd'hui uses (the mutation id
born at the tap), then enqueues the drain (SPEC 13.2). No success animation - the
sheet closes and the cell updates by observing the repository. A future or
out-of-period day is not recordable, so openDay refuses it and its cell is inert
(AC1). The sheet content is a standalone composable baselined directly, because a
ModalBottomSheet's own scaffolding does not render reliably under Layoutlib. New
baseline: calendrierEditSheet, looked at.

THE RECORD MADE VISIBLE (increment 3, AC2)
--------------------------------------------------------------------------------
NOT BY COLOUR ALONE. A quality legend (RecordQualityLegend) names the three bar
colours in words - "A temps", "Saisie tardive", "Non renseigne" - beside the kind
legend. No corrected-line: the manual product has no detection, so a cell can never
carry the corner mark, and a legend line for a feature the product lacks is what
R282 forbids (named in FD6 AGAINST THE RULINGS).

LATE COMES FROM THE SERVER'S ROW (R216). CalendarModel.serverLate is the ONE home
for the rule: true only once a row is SYNCED and its own firstRecordedAt is more
than the threshold after the day, by the SAME rule the server's late.ts uses
(LatenessForecast.wouldBeLate, bound to fixtures/late-threshold-cases.json). Read by
both the grid cell (qualityOf) and the edit sheet, so the two cannot disagree. A
row the server has not yet seen is PENDING, never LATE.

THE SHEET STATES THE FLAG OUT LOUD (SPEC 11.3), R216-split: a synced late day
states the FACT ("Saisie tardive : enregistree plus de N jours apres la journee.
Cette mention figure dans votre releve annuel."); a still-unrecorded backdated day
PREDICTS ("...sera signalee comme saisie tardive des sa synchronisation..."). The
threshold N is interpolated from LatenessForecast, never a typed 7 (R153/R181). The
provenance block shows "Saisie manuelle" (one home, AujourdhuiCopy.MODE_MANUAL,
R206), the server's first-recording timestamp, and - when the day was changed after
that - the modification timestamp (both the server's own values, read Paris-side).
Baselines regenerated (R135/R207): calendrierMonth (quality legend added),
calendrierEditSheet (provenance block added), calendrierEditSheetLate (new). All
looked at.

THE LIST (increment 4, AC3) -- the measured threshold, and how
--------------------------------------------------------------------------------
Seven columns cannot hold 200 percent text, so above a font scale the grid becomes
a list (CalendarList): one row per day, each saying date, kind, quality and
provenance IN WORDS. The switch reads LocalDensity.fontScale against
LIST_FONT_SCALE_THRESHOLD, a behavioural constant (not a design token). The word
homes are reused (kind from LegendCopy, quality from CalendarCopy.qualityWord,
provenance from AujourdhuiCopy).

MEASURED ON THE DEVICE, not chosen. The emulator's system font_scale was swept and
each result looked at:
  1.45  the GRID: day numbers large but the seven columns still fit, the header,
        both legends and the summary all readable. LEGIBLE - the last legible step
        below the switch (shot cal-scale-1_45).
  1.5   the LIST takes over - "Mardi 1 septembre 2026 / Non renseigne", one row per
        day, weekends showing the date only (shot cal-list-1_5).
  2.0   the LIST, each row large and legible with its words (shot cal-list-2_0, and
        the calendrierListLarge Paparazzi baseline: on-time, late "Saisie tardive",
        pending "En attente de synchronisation", missing "Non renseigne", weekend
        date-only, absence).
THE MEASURED FIGURE: the grid stays legible through fontScale 1.45; the list takes
over at 1.5, which is the shipped threshold. New baseline: calendrierListLarge,
looked at.

THE EDIT SHEET AT 200 PERCENT (commit 8284493, the night's default-AND-2f
discipline). The sheet was this task's main new surface and had only default
coverage, so calendrierEditSheetLateLarge photographs its richest state (late +
modified) at 2f: title, question, options, note and the late notice all wrap
legibly; the content scrolls, so Enregistrer and the full provenance sit below the
fixed viewport (seen at default in calendrierEditSheetLate and on the device in
cal-10/cal-11). Looked at.
