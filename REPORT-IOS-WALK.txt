SUMMARY
================================================================================
The walk's whole infrastructure works on the macOS runner and has never leaked: a throwaway PostgreSQL and scratch
database made by the project's own mechanism, web/'s dev server asserted by name, secrets born and masked on the
runner, a Debug build pointed only at a runner-local relay, an upload allowlist and a secret scan that passed on
every run, and an app log uploaded only after a grep for every code and token returned 0 lines.

The XCUITest driver reaches the Compose UI only because the simulator's VoiceOver preference is set: Compose
Multiplatform 1.7.3 syncs its semantics tree to UIAccessibility ONLY while VoiceOver reports running. With that,
DRIVER PROOF (a) passed (a Compose element found by its accessibility label and tapped), and a CODE SIGN-IN
passed end to end three times (runs 45075605782, 45078149756, 45081978093).

THE WALK STOPS at onboarding's second screen. The canton "Geneve", below the fold, reaches UIAccessibility with a
ZERO frame {{0,0},{0,0}} and is never hittable. Three runs failed there: 45075605782, 45078149756 and 45081978093.
Run 45084504474 tried the screen's own search field but failed EARLIER, at sign-in: a key tap was lost. Run
45088845825 tried a read-back of the typed e-mail and made typing worse. It was reverted. The code tip is the run-8
driver plus the search-field step.

DRIVER PROOFS (b), the notification alert, (c), the native date picker, and the background/foreground were NOT
reached. Nor was anything after onboarding: M4, M3, the tap, the years and the plan, the export, Parametres, or a
recorded day on the server.

R1340 - THE SERVER IS THE RUNNER'S OWN
================================================================================
- POSTGRES ON macos-15: MEASURED ABSENT. initdb, pg_ctl, psql and postgres are not on PATH, there is no Homebrew
  postgresql keg and no docker (run 45055507141, step "Directories and runner facts"). The workflow runs
  `brew install postgresql@16` (16.16) FOR THE RUN ONLY. That is a runner tool, in no package.json, gradle file
  or lockfile.
  initdb uses scram-sha-256 and a generated password; the server listens on 127.0.0.1:55432; its log is never
  printed; its data directory is deleted at the end.
- THE PROJECT'S OWN MECHANISM, UNCHANGED (R206): gate-clone-parts.mjs's administer() (DROP/CREATE through the
  server's `postgres` database), scratch-database.mjs's scratchDatabaseName('ios_walk_<run>'),
  scratchDatabaseUrl(), then `pnpm db:deploy` ("17 migrations found"). Nothing in web/ was changed.
- THE SERVER: `pnpm dev` (NODE_ENV=development, FRONTALIER_RUNTIME unset) on 127.0.0.1:3311, its stdout and stderr
  to a private file. R169: /api/health answered service 'monreleve', the expected value read from
  web/identity.json, on every run, both direct and through the relay.
- THE BUILD: MONRELEVE_API_BASE_URL overridden on the xcodebuild command line with http://127.0.0.1:3310 (the
  relay). The built Info.plist is asserted to carry it, and asserted NOT to name the production domain (read from
  identity.json at run time, so the workflow file never types it). ATS: none added; loopback http works, as R1320
  measured.
- No production URL, host, database, Coolify resource or credential is in ios-walk.yml, the helper, the test
  sources or the logs. A grep for the production host over every file this session added finds 0 (one test note
  that named it was reworded before this report).

FINDINGS
================================================================================
F1. COMPOSE'S TREE IS INVISIBLE TO ANY ACCESSIBILITY CLIENT EXCEPT VOICEOVER. The cause is Compose Multiplatform
    1.7.3's default AccessibilitySyncOptions.WhenRequiredByAccessibilityServices, which reads only
    UIAccessibilityIsVoiceOverRunning(). XCUITest saw an EMPTY window (run 45055507141). The same holds, by the
    same code path, for Voice Control and Switch Control: it is inferred from the source, not measured. For
    IOS-AUDIT.
F2. THE ZERO-FRAME BUTTON (the orchestrator asked for it as a FINDING, not a test defect; nothing here shows the
    driver at fault):
    - In the canton list, every canton outside the viewport reaches UIAccessibility as a Button with frame
      {{0.0, 0.0}, {0.0, 0.0}}. In run 45078149756's tree, Geneve..Soleure are zero after scrolling, while the
      rows on screen (Schwytz..Zurich) carry real frames.
    - XCUITest's tap needs a hittable element, and it cannot scroll an element to a position it is told is
      nowhere. Flings, and short drags from the top, never produced a hittable Geneve in the snapshots taken
      between drags.
    - DIAGNOSIS (argued, not proven): Compose reports an off-viewport node's AX frame as zero rather than its
      off-screen position. The snapshot did not show Geneve with a frame at any point the walk looked, including
      on the way back up.
    - Whether VoiceOver's own scrolling reaches such a row is exactly IOS-AUDIT R1355's measurement.
F3. A COMPOSE TEXT FIELD is an unlabelled Button whose label becomes the TYPED TEXT, and XCUITest's typeText is
    refused on it. Typing works only through the keyboard's keys, and it is not reliable: 1 lost tap in run 9, and
    in run 11 a sequence never registered. This bears on R574: a code box's label holds its digit.
F4. PostgreSQL is not on the macos-15 image (and docker is absent).
