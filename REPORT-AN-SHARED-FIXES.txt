R1092 - THE FILENAME, A TEST FIRST
======================================================================================================
The decision as implemented, in AuthApi.kt: filenameOf(...)?.trim()?.takeIf(::isPlainFileName).
isPlainFileName requires:
- the name is not empty;
- the name is not "..";
- no character is "/", "\", or a control character (Char.isISOControl: C0, DEL and C1, NUL
  included).
Once both separators are refused, ".." can only be a path segment by being the whole name.
"releve..2026.pdf" therefore stays a plain name, and a test pins that it passes.
A refused name is null, exactly as an absent one, so each controller's existing
`?: fallbackFilename(kind)` applies (ReleveController.kt:306, ParametresController.kt:418).

commonTest - shared/src/commonTest/kotlin/ch/monreleve/app/data/remote/FilenameOfTest.kt (10 tests;
runs on the JVM here and on the iOS simulator in the R573 run):
- Refused: slash shapes ("../../files/evil.pdf", "exports/x", an absolute path); backslash shapes;
  NUL, U+0001, LF, DEL and U+0085 inside the name; ".." and "  ..  "; blanks; an empty quoted
  name.
- Pass-through: no header and no filename stay null; "releve..2026.pdf" and "releve-2026...pdf"
  pass unchanged; a lower-case header name with blanks passes "releve-2026.pdf".
- R204, through the real export entry AuthApi.authenticatedGetBytes: a hostile header gives
  ExportBytes.filename == null, and a plain one passes unchanged.
