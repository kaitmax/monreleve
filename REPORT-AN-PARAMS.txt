DEVIATIONS
--------------------------------------------------------------------------------
1. A prior agent's uncommitted modifications were lost to an orchestrator
   `git checkout -f`; this session redid them (the integration of the five
   extracted files). The goal was a clean green AN-PARAMS, not preserving every
   inherited line - some inherited code was rewritten to make it consistent.
2. ParametresSettingsColumn takes no `modifier` (it would be a 6th parameter and
   detekt's LongParameterList fires at 6 in this project; a @Suppress is barred by
   Fence 4). The sole caller (MainActivity) passes no modifier and the host shell
   owns the screen padding, so nothing is lost; ParametresScreen's own `modifier`
   still reaches the LicencesScreen branch. Reversible if a caller ever needs it.
3. The on-device PERSIST (save -> /api/v1/me -> phase SAVED -> the row shows the
   new value) was not demonstrated on the phone: the debug APK targets
   http://10.0.2.2:3000 (the emulator's host alias, unreachable from a physical
   device) and the walkthrough injects a fake session, so the PATCH cannot
   authenticate. On tapping Enregistrer the sheet correctly shows "Enregistrement
   impossible. Verifiez votre connexion" (the frame.error path, p-52). The persist
   is HARD-boundary-unchanged (ParametresController) and was server-proven in AN12;
   the committed-snapshot wiring's complement is shown (Annuler/edit leaves the row
   unchanged). A backend + real sign-in (frontalierHost=127.0.0.1 + `adb reverse`)
   would close it - see QUESTIONS.
4. CompteSection shows NO email row (carried from AN12): the device stores only an
   opaque account tag, never the address; surfacing an email would need a schema or
   a /v1 read, both HARD boundaries, and "never claim more than the record supports".
5. The walkthrough helper scripts/an-params-walkthrough.mjs (untracked, as every
   prior task's walkthrough is) was fixed to: normalise the typographic apostrophe
   and narrow/no-break spaces before matching; search both scroll directions and
   skip zero-area nodes; use the proper kill-restore technique; and select a picker
   day before confirming. It drives the app; it is not app code and is not committed.
