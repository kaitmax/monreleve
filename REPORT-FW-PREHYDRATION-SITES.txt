QUESTIONS
====================================================================
Q1. THE CALCULATOR'S SHARED LINK, the premise. Web Ruling 36's default reads
    "the server renders the shared link's values into the fields". It does
    not: the page is static (its own header: reading searchParams moves the
    canonical out of <head>), so before hydration a shared link shows the
    DEFAULT form and the link's values arrive on mount. Implemented: per
    control, touched wins, untouched takes the link. Consequence: a reader who
    edits a default-looking field on a slow phone then sees the OTHER fields
    jump to the link's values at hydration, their edit kept. The alternatives
    are the operator's: (a) keep this; (b) any touch discards the link
    entirely (an untouched canton then stays empty); (c) render the link on the
    server (the canonical ruling would have to move).
