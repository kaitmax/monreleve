INCREMENT 0 - R44 TO R48
================================================================================

Carried out across two commits before increment 1.

R46 - TICK_WIDTH 1,5 -> 2. RED first: "expected 1.5 to be 2". The deciding
evidence was the device pixel grid rather than either design brief: at 1,5 px
the two ticks rendered ASYMMETRICALLY FROM EACH OTHER in the 200 px baseline,
one a symmetric grey pair and the other lopsided, because a 1,5 px rect lands
on a half-pixel wherever its centre falls. Two marks meant to read as
identical looking different is a defect in the one element that has to read
as authoritative.

R45 - band names leave the SVG. Centring them over their bands cannot work at
any realistic width: "Imposition France" measures 93,7 px at Micro 11/500
over a band that is 9,9 % of the track, so it needs roughly 950 px of rail
before it stops colliding. inline and compact now carry none; social keeps
them as a left-anchored stack below the rail. A consequence with its own
test: inline and compact emit IDENTICAL SVG, the band names having been the
only thing separating them.

R44 - the social card carries no rate, no fill and no band colour, because a
fill length IS the rate. On the operator's question - optional field or
ignored field: IGNORED, guaranteed by a test rather than a type. Making
percentage optional would split RailData into a union, change the shape SPEC
6.3 states, and push a discriminated check into every caller to express
something the caller does not need to know. rail-render.test.ts instead
renders social twice, with 4,16 %/compliant and 97,5 %/social-switch, and
requires the two strings to be BYTE-IDENTICAL.

R48 - the social card carries the zones themselves: three static band fills
derived from the thresholds alone, so R44's byte-identity survives untouched.
SOCIAL_TRACK_HEIGHT 16 is a documented exception at the site to
DESIGN-SYSTEM.md's "never taller than 8", scoped to that variant and
asserted; the other two are tested to keep TRACK_HEIGHT.

R47 - the PAT. gh auth status showed only the device-flow credential (gho_,
scopes gist, read:org, repo, workflow). The pasted token was NOT revoked at
that point: it still returned HTTP 200 on /user. Reported, not used again.
See QUESTIONS FOR THE OPERATOR - this is now blocked on you.

Coverage caught a real defect during increment 0: pairing the band rows by
index needed an undefined check that is unreachable, which lib/ui/core's
100 % branch gate cannot cover. The geometry now emits zone-and-baseline
PAIRS so the renderer does no indexed access at all, and the refactor was
verified byte-identical before the baselines were trusted.

R62 - THE SIZE TOKEN FAMILY. --size-icon-sm 16, --size-icon 20, --size-icon-lg

fitted the chip icon; --radius-checkbox is 6 px and would have fitted the dot.
Borrowing either is exactly the semantic aliasing DESIGN-SYSTEM.md 4.1 removed
from the radius scale.

All three call sites close. The most satisfying is TICK_WIDTH: for two
increments its test pinned that 1,5 px was in NO token family and said so out
loud, ending "if a token for it ever appears, this test fails and the constant
should become a mirror". It appeared, and it did. The legend dot goes back to
the 6 px the brief asked for, having been 8 for one increment because no token
carried 6.

A distinction the document now carries: sizes a component measures in CODE -
the rail's geometry - mirror these BY TEST rather than referencing them,
because an SVG geometry attribute resolves var() to ZERO when no cascade is
present and the track vanishes silently.

R63 - THE SILENT-SUITE FAILURE. A vitest include glob that stops matching
removes its files from the run, every assertion they carried stops being
checked, and pnpm test still exits 0.

This repo had already met the near miss: FW8's component tests are .test.tsx
and the glob then ended in .test.ts, which matches neither. It was caught only
because those tests were NEW and someone was waiting to see them run.

Detection has to come from OUTSIDE the run, because a file that did not run
cannot fail:

  4 canaries    tests/ and lib/, .ts and .tsx, one per (directory, extension)
                pair. Each asserts only that it was collected from that
                directory with that extension. The .tsx pair holds no JSX
                deliberately, so it can fail for exactly one reason.
  meta test     reads the config MODULE, not its text, and requires a canary
                for every pair, so the scheme extends itself.
  floor script  requires vitest to have collected every canary, and holds
                counts that may only go up.

TWO SOURCES, BECAUSE THEY SEE DIFFERENT THINGS. vitest list is a STATIC
collector - measured, not assumed: it renders ZoneBadge's looped block as
"... > status > renders the label" with the loop variable unresolved, and
counts 11 call sites where 21 tests run. Cheap enough to run before the suite
and right for "did the glob match this FILE", but blind to a parametrised
block whose fixture array was emptied. So the file floor and the canaries come
from list; the TEST floor is read from a real run's JSON report, which CI gets
free as a second reporter.

The three falsifications, each run and each red:

  glob drops tsx    floor names both .tsx canaries as uncollected, 36 files
                    against a floor of 40. The suite under that same broken
                    config reported "676 passed" - ZoneBadge and ThresholdRail
                    simply gone, green but for the meta test.
  canary deleted    meta test red, naming the missing path
  fixture emptied   list unchanged at 426 call sites; the runtime report fell
                    711 -> 699 and the floor caught it. This is the case that
                    justifies --report existing at all.

Also widened the eslint spike-quarantine block from tests/**/*.ts to
tests/**/*.{ts,tsx} (and e2e likewise) - the identical silent-miss defect one
layer over, no longer theoretical now that tests/ holds a .tsx file.

CONTRAST AUDIT
================================================================================

tests/unit/tokens/contrast.test.ts. Ratios computed from the COMPILED tokens -
tokens.scss is compiled in the test, the way radius.test.ts does it - so the
audit and the palette cannot drift. A hardcoded table of hex would be a second
copy of the palette that keeps passing after the palette changes.

R59'S TWO GATES: 4,5:1 normal text, 3,0:1 large text and non-text. One gate
would be wrong in both directions. At 4,5 everywhere the Display rate in the
warning band fails, and it is 48 px, which nobody has trouble reading. At 3,0
everywhere the ZoneBadge label passes at 15 px, where the same colour
genuinely is hard to read.

Where WCAG is ambiguous the audit takes the stricter branch. WCAG says "bold"
without naming a weight; the conventional reading is 700, so the H3 second
rate at 20/600 is held to 4,5 rather than argued into the large-text gate. It
clears 4,5 anyway.

68 assertions in two blocks.

THE HAND TABLE covers the pairs whose background is not a surface, or whose
foreground arrives dynamically: the badge label on each of the three soft
fills, each status icon on its own fill, each band colour at Display, the rail

The comment and the prop check are there because the COUNT alone would not

width, with every text node escaped by xml.ts, and there is no prop through
which a caller-supplied string could arrive. None of that is visible at a
second call site written six months later by someone who saw this one and
copied it, which is how a sanctioned exception becomes a pattern.

app/dev/rail-gallery stays outside the scope but NOT outside review: a second
test requires every occurrence in the WHOLE repository, dev included, to carry
an eslint-disable naming a reason after "--". A bare directive silences the
rule without recording why. So every site in the repository is covered by one
test or the other.

DEVIATIONS
================================================================================

1. LEGALNOTE IS SECONDARY, NOT TERTIARY. The prompt says "Caption tertiary".
   Ruling R58 says secondary, and the measurement agrees: #98A2B3 is 2,42:1
   on the canvas and 2,58:1 on a card, failing AA at both bars. Setting the
   legal disclaimer, of all text, in the one colour nobody can read would be
   a poor joke. Implemented as R58.

2. THE ZONEBADGE LABEL IS TEXT-PRIMARY, NOT THE WARNING COLOUR. The prompt
   allows "the label inside the chip may use the warning colour at 15/500 on
   its soft fill". Ruling R57 overrides it, and the measurement is why: that
   pair is 3,42:1, and the same increment's AC2 demands a passing contrast
   audit. The warning colour survives where it is legal - the icon, and the
   Display rate.

3. THE DIVERGENCE SENTENCE CARRIES NO NUMBER. SPEC 9.3 phrases the
   explanatory line as naming the 10-DAY CAP. The cap belongs to the year's
   RuleSet (SPEC 7.7), and a threshold written into copy is a second source
   of truth that goes stale in silence - the sentence would still say ten
   after the rule changed, and nothing would fail. "Le plafond annuel" says
   the same thing and cannot drift. Same rule statuses.ts already carries.

4. AXE RUNS VIA vitest-axe, NOT jest-axe. The prompt says jest-axe; vitest-axe
   was already installed under R56 and is the same axe-core with a vitest
   matcher. Reading it as the intent rather than the letter.

5. THE RAIL'S VARIANT x ZONE BASELINES ARE NOT DUPLICATED ON THE WORKBENCH.
   The prompt asks for a baseline per component per state. rail-gallery
   already holds ten over that matrix, taken in the same container. A second
   set would double the maintenance and halve the meaning of a diff - two
   files to update and a reviewer asking which is the contract. The one rail
   state rail-gallery does NOT cover, unavailable, is on the workbench.

6. THE MINUS-SIGN E2E TEST WAS WRONG ON ITS FIRST RUN, and the page was
   right. Read over the whole specimen it failed because the replacement
   label "Jours au-dessus du seuil" contains a hyphen - as does any compound
   French word. The claim was never "this card contains no hyphen"; it is
   "the number carries no sign". Scoped to the figure.
