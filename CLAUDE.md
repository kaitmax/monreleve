# CLAUDE.md — frontalier

A French-language product for cross-border workers who live in France and work in Switzerland. It answers one expensive question — how many telework days are left before the 40 % fiscal threshold and the 49,9 % social-security threshold — and produces the **Relevé annuel de télétravail**, an audit-defensible PDF in which every recorded day carries a server-assigned timestamp and its provenance.

One backend, two clients: a public Next.js site (`web/`) and an Android app (`android/`).

---

## Ignore any CLAUDE.md above this directory

If a `CLAUDE.md` exists in a parent directory, **it belongs to a different project** — a Morocco trekking/desert travel platform, with `next-intl`, `messages/{fr,en}.json`, a `wa.me` handoff, agency approval flows and commission maths. None of it applies here, and following it would actively break this product:

| That project says | This project requires |
|---|---|
| `messages/{fr,en}.json` for user-facing strings | `lib/fr` only — single-locale French, **no i18n abstraction** (SPEC §1 non-goals) |
| `app/[locale]/…` route groups | no locale segment; one locale by design |
| agencies, trips, leads, commission | none of these concepts exist |

Read it as belonging to a neighbour, not as instructions. This file and `README.md` are the authority for this repository.

## Rules that are never relaxed

- **One task per session.** The prompt names it. Nothing outside it is touched; out-of-scope observations go in the report under *NOTICED BUT NOT TOUCHING*.
- **Commit only on green, and green is the gate for the paths you changed (R132).** `pnpm gate:changed` reads `git diff`, prints the suites it selected, and runs them chained so a failure cannot be followed by a commit. `typecheck`, `lint`, `test` and `build` always; **plus `test:e2e` and `test:visual`** when any changed path matches `app/**`, `lib/ui/**`, `lib/fr/**`, `**/*.module.scss`, or the token layer. Paste the printed selection into the commit body. A red commit is a bounce.
  - This bullet used to name the four-command chain alone, and FW13 put two red commits on main under it: both changed a component, neither ran e2e or the baselines, and both failed CI on exactly those. The selection is made from the diff because the judgement version — *run the visual suite when you think you changed pixels* — is the version that failed.
  - `test:a11y` is deliberately **not** selected: its three files are a strict subset of `pnpm test`'s globs, so requiring it is a second execution rather than more coverage. The printed selection still names it, so its absence reads as a decision rather than an omission.
- **`pnpm gate:clean` runs once on an increment that adds a dependency, reads a new environment variable, or changes a build or postinstall step (R139).** Not on every increment — it is about two minutes. It copies what git would hand a fresh clone into a temp directory (so `.env`, `node_modules` and every other ignored path are absent *by construction*, not by a scrub list somebody maintains), then installs, typechecks and builds there with the known secrets stripped from the environment.
  - It answers a question `gate:changed` structurally cannot. FW14 put two red commits on main where **every selected suite ran and passed** — the failures were a generated Prisma client that existed on this machine and not on a fresh install, and a `.env` that exists here and not in two of the five CI jobs. *"It passes here"* and *"it passes on a clean checkout with no secrets"* are different claims.
  - Proven by restoring each failure: the import-time client fails its `build` with *Failed to collect page data*, and a missing `postinstall` fails its `typecheck` with *no exported member 'PrismaClient'* — the same messages CI produced.
- **Test-first.** New behaviour gets its failing test before the code, and the report shows the RED run with the reason it failed. A test that passed on its first run is evidence of nothing.
- **A regenerated baseline needs a stated reason (R135).** `--update-snapshots` rewrites the visual record to match whatever the page currently does. Any commit that regenerates baselines lists the files in the report, with what changed and why it was expected; `pnpm test:visual:update` prints that list ready to paste. A baseline suite certifies that *nothing changed* — never that what exists is *right*, and it will happily certify a wrong-but-stable layout for as long as it stays stable. The only thing that catches one is a person cropping the image and looking at it, which is how FW13 found a share row sitting above the notice that explains it, and a 22 px copy button where FD1 says 48.
- **Design tokens only.** No raw hex, radius, spacing or type value outside `lib/ui/core/styles/tokens.scss`. Radius is a closed set of nine token names (`DESIGN-SYSTEM.md` §4.1).
- **French strings only in `lib/fr`.** Never inline in JSX; `react/jsx-no-literals` enforces it.
- **Copy in a format that cannot interpolate names the rule, never its value (R153).** A guide's prose can write `{fiscal}` and take 40 % from `RuleSet`; its FAQ frontmatter is YAML and cannot, so the answer says *le plafond fiscal* instead. The same holds for every surface with no expression: email templates, push-notification bodies, Android string resources. A figure typed where a constant cannot reach it is the copy that goes stale in 2028 with every test still green.
  - The rule arrived because YAML forced it. FW17 could have added a workaround — an interpolation pass over frontmatter — and the stricter reading is better copy: *le plafond fiscal* stays true when the plafond moves.
  - **Where both forms appear, the prose is the authoritative one** and the article shows it: figures live in the prose, names in the FAQ. A reader must not meet a value in one place and a name in another for the same rule without knowing which to trust.
  - R147's scan covers guide frontmatter, so this is enforced there today.
- **A mechanism is proven to deliver, not proven not to fail (R154).** Every substitution, interpolation or generation step gets a **positive** test: a known input produces the known rendered output, asserted against the served HTML. The same shape as R133's positive-signal rule, one layer up.
  - It exists because `next-mdx-remote` defaults `blockJS` to **true** and silently deletes every MDX expression and every JSX attribute expression. Every guard passed because there was nothing to find: the build succeeded, the frontmatter parsed, the claims resolved, and R147's typed-number scan found no typed figure **because the figure had been deleted**. The pillar would have shipped reading *jusqu'à de son temps de travail annuel*, and the next baseline would have photographed the hole and certified it.
  - The guard was verifying the absence of the wrong thing rather than the presence of the right one. An absence assertion is satisfied by a mechanism that produces nothing at all.
- **`lib/fr` is authoritative and fully accented (R155).** ASCII in a relay prompt is *illustrative, never a source*: the prompt's spelling is a transport constraint, and any copy taken from one is re-accented before it lands. A forbidden-forms guard enforces it over `lib/fr` and `content/guides`.
  - The list is **curated, not derived**. Stripping accents from correct French proposes `votre`, `des`, `sur`, `compte`, `entre` — all correct spellings of different words. It is a list of the words this product uses, extended when one appears.
  - Identifiers live inside quotes too: `/releve-annuel`, `regime-lost`, `NEGATIVE_DAYS` and every guide slug must not be flagged. Prose contains a space; an identifier does not.
  - With R91 (typography), R126 (apostrophes) and R153 (name, don't quote), this completes the copy-integrity family — four guards on one surface, each added after it was breached.
- **A source key identifies a fact, not a URL (R158).** Three facts sharing a citation is normal; three facts sharing a **key** means the claims test cannot tell them apart. Every distinct regulatory fact an article may cite gets its own id in `SOURCE_IDS`, even when two ids point at the same page.
  - FW17 and FW18 cited the mission travel-day rules *and* the six Geneva worked examples under `missionCapDays`, because all three are published on the same ge.ch page. `claims` could then not distinguish *the cap is ten days* from *a travel day worked mostly in Switzerland is not counted*.
- **The table scrolls, never the page (R159).** A comparison table that cannot fit the viewport gets its own `overflow-x` container, with the scroll made **visible** rather than implied. R127 is unchanged: the page body never scrolls sideways.
  - Two of two comparison tables written in FD13's shape overflowed 320 dp and were each fixed by transposing them — a per-author decision made twice. The kit answers it once.
- **The reviewer chip states the status, not a name (R160).** Until a named expert reviewer exists it reads *Relecture experte : en attente* and links `/sources`. It does not name the team: *Relu par l'équipe frontalier* implies a review that has not happened, which is the same defect as a present-tense privacy claim — on the surface whose whole argument is that it claims no more than the record supports.
- **An internal register never shares a namespace with a published one (R162).** `parking.md` numbers its entries `PARK-<n>`; the reader-facing ids in `lib/content/provisional.ts` keep `P<n>`. Where a rename is needed it is the internal side that moves — renaming user-facing references to resolve an internal collision is backwards, and a published anchor is a URL that SPEC §14 makes permanent.
  - It is not a tidiness rule. While both registers used `P<n>`, FW18b wrote *"P6 supersedes P2"* meaning the parking entry — and read against the published register that sentence says the 49,9 % interpretation had been withdrawn. **A namespace collision produced a factually wrong statement about a regulatory interpretation, inside the file that exists to keep decisions traceable**, and no test could see it because each register was internally consistent.
- **Prose that narrates a fixture is tied to the fixture (R163).** The Geneva worked example lives in the file the engine is gated on. A guide narrating it interpolates from that file, or — where a narrative passage cannot hold expressions — a test asserts every number in the passage equals the fixture's.
  - R147 forbids a typed **figure** and cannot see a typed **derivative**. Two articles narrated the example as *credités : {missionCap} … comptés : 94 … taux : 39,16 % … imposables : 14*, where three of those four are computed by hand from the cap. Move the cap to 12 and the passage contradicts itself in one breath: *seuls 12 sont crédités, et les 14 autres deviennent imposables*. A derivative is not a figure, but it **is** a value from a fixture, and that is checkable.
- **Retrofitted copy is written, never lifted (R165).** Copy for a component retrofitted across several pages is authored per instance or written generic. It is never taken from one instance and reused in the others.
  - FD13's inline card took the pillar's own lead-in — the best sentence in the set, and true in exactly one place. On the droit d'option guide it sat directly beneath a paragraph saying the telework threshold has no bearing on that choice, and then explained telework arithmetic. **One constant rendered in seven articles has to be true in all seven.**
- **A citation names the instrument, not its current file (R167).** A source row's identity is the instrument's name — *« Choix du système d'assurance maladie »*, *circulaire n° 45* — and any URL is recorded with a fetch date as a convenience that is allowed to rot. A dead PDF link is a maintenance item, never a claim becoming unsourced.
  - R153's shape one layer out: copy names the rule rather than quoting its value; a citation names the instrument rather than pinning its file. The case that produced it is the CLEISS option form, whose address carries `juin2019` while the page itself says it is being updated — and it generalises to the BAG cantonal-body list, to any AFC circular reissued under a new reference, and to the priminfo XLSX if it ever lands.
- **No relay prompt carries a French quotation (R168).** Prompts are ASCII by transport constraint (R155), so a quotation passing through one becomes transliterated copy — the exact defect R155 exists to forbid. A prompt points at where the accented original lives.
- **A rule with no enforcement point is a comment.** R85 - a target renders only when it is live - existed from FW9 and the shell never applied it, so the nav and footer linked two dead routes from every page for eleven tasks. The registry test asked whether each href was DECLARED and the sitemap test asked whether a planned route was LISTED; nothing asked whether the thing a reader clicks answers. FW20 closed it under PARK-12.

- **The suite asserts what it is pointed at, first (R169).** A Playwright global setup fetches `/api/health` and refuses the entire run unless the response *names this product* — a `service` field, not merely a 200. A foreign or missing answer aborts before a single spec executes, with a message naming what was found and suggesting a port collision.
  - **Measured cost of not having it: 91 tests passed against a different application.** FW20 opened with the suite attached to another project's container on port 3000 and ran it to completion.
  - **A health check that only proves something is listening proves nothing about what.** The foreign app answered `/api/health` with 200 and valid JSON of its own, so the obvious guard would have passed and released all 91. This is R133's positive-signal rule one level up: the signal has to be specific enough that only the right thing can produce it.
  - **Corollary — an absence assertion is only meaningful once presence is established.** *Absence assertions are satisfied by absence*: `/sources` 404s on a foreign server, a 404 page has no horizontal overflow, so every R127 check holds — and "every element is inside the viewport at 320 dp" holds because all of nothing is inside it. R127's checks, the singleton censuses and the third-party traces each require a served 200 before measuring.
  - It earned a defect on its first run. `e2e/analytics.spec.ts` had requested `/alertes/desinscription/desinscrit` since FW14; the valid states are `ok` and `invalide`. **The route was certified clean by never being loaded.**
- **The port comes from the environment (R170).** `BASE_URL` reads `FRONTALIER_PORT`, then `PORT`, then 3000, from one module used by both the webServer and the tests. Freeing a contended port fixes today; a port that can move fixes it for good. `reuseExistingServer` stays — reuse is only unsafe while nothing establishes whose server is being reused, which is what R169 now does.
- **Statements about the product's own state come from one module (R172).** `lib/content/product-state.ts` holds the facts — `dossierExists`, `trackerExists`, `comparatorExists` — and every page derives its sentence from them, the way the footer derives from `LAST_REGULATORY_REVIEW`. A flag flips once and every page that depends on it changes together.
  - FW20 wrote three pages in one task, each internally consistent, and the contradiction lived only between them: `/a-propos` said the site *tient un registre de journées*, `/tarifs` said *le relevé* was free, and `/releve-annuel` said the register *ne sont pas construits*. **No test can see that**, because each page is right about itself — the same shape as the P-register collision, one subject over.
- **An unstyled anchor is impossible, not merely discouraged (R173).** `a` takes the link token in the base layer, with a test asserting no rendered anchor resolves to the user-agent default.
  - It shipped three times — `.breadcrumb`, R160's reviewer chip, the home page's two doors — each time in default browser blue against grey prose, each time invisible to every gate and found by cropping a baseline. **Third shipping is the signal R149 describes: the defect is in the guard, not the component.** Fixing it a fourth time in a fourth component would guarantee a fifth.
- **Where two tests bound a property from opposite sides, something asserts the space between them (R175).** When a property is fenced from two directions, name what lies between and assert it — **in the suite, never as prose in an acceptance criterion.**
  - PARK-12: the registry test asserted every rendered href was *registered*; the sitemap test asserted no planned route was *listed*. Both passed for eleven tasks while every page linked two dead routes, because between "declared" and "in the sitemap" sat **"linked from every page and broken"**. Neither test was wrong; the space between their scopes was unexamined. todo.md's zero-404 check sat unexecuted as prose for those eleven tasks.
- **Every task ends with the server run and driven (R176).** Not a smoke check: open the pages the task touched, use what it built, and follow the links out of it. The report gains a **WALKTHROUGH** section recording what was driven and what it showed.
  - It is a distinct instrument. The read-through reads copy **across** pages and catches contradictions between them; baselines compare pixels to a stored image; the walkthrough catches a rendered page contradicting **itself** — a lead against its table, a heading against its content, a count against its list.
  - **A read-through instruction names where difficulty is expected without exempting anything else.** FW20's prompt named `/a-propos` and `/tarifs` as the pages to scrutinise, and `/sources` — which was miscounting itself by six — received a pass by omission. Direct attention, never restrict it.
- **The walkthrough runs against `pnpm dev`, and the baselines must agree with it (R177).** Any divergence between what the dev server serves and what the container photographs is a defect in the pipeline, not a quirk to route around — a suite that only ever sees built output cannot tell you the development path is broken, and every session is developed on that path.
  - Operationally: the e2e run and any measurement tool assert the page under test **has styles** — the compiled stylesheet is fetched, is non-empty, and contains a known token declaration — before asserting anything about it. This is R169's presence corollary applied to CSS.
  - **A Lighthouse run against a page whose CSS failed to load reports a perfect performance score**, because there is almost nothing to paint: *the metric improves as the product breaks.*
- **Where a guard's first run finds live instances, those are the proof (R178).** The planted violation is redundant. A planted case proves the guard *can* fire; shipped instances prove the class existed and was invisible. Where both are available the report leads with the real one.
  - R173's anchor test found **fifty unstyled links live** on its first run — every guide's `/sources` footer link and all six related-guide links, on all seven articles. Four tasks of cropping guide baselines had missed them because they sit below the CTA card and every crop was of the article head. **A crop is a decision about where to look, and the defect was below the fold of that decision.**
- **A sampled measurement gets a better sample, never a looser gate (R174).** Lighthouse runs three times and asserts the median, with the floor unchanged at 100, and it checks `/api/health` identifies this product before it measures anything — R169 extended to the tool that did not have it.
  - FW20's floor failed once at 0.99 with `numberOfRuns: 1`. R114's no-tolerance rule governs **baselines**, where a diff means something changed; Lighthouse is sampled, so 0.01 is noise and the answer is more samples rather than a widened band.
- **A harness kills the tree it spawned, and asserts the port free before it starts (R179).** Both halves, because either alone leaves the trap: killing the tree without the precondition still inherits an orphan from a previous crashed run; asserting the port without killing the tree creates the orphan the next run inherits. And a stale server must fail **loudly as a stale server**.
  - `spawn(…, { shell: true })` returns the SHELL's PID, so `kill()` took `cmd.exe` and left `next start` holding the port. The orphan then served a build whose CSS the *next* build had replaced, and the stale hash read as a broken stylesheet — **the symptom presented as a broken stylesheet, which would have sent the next session hunting the wrong defect entirely.**
  - What makes it worth a rule is the causal loop: **the script created the orphan, and then the guard the same script added caught it.** R98 covered containers, R105 processes on expected ports, R131 the working tree — this is a process the harness itself spawned and believed it had killed.
  - **Refusals are labelled by the rule that raised them.** A small thing with outsized value at 2 a.m.: R169 and R177 both aborting the run with the same message would have cost someone an hour.
- **A plant is verified before its result is read (R180).** Confirm the file actually changed, and that the change landed **where it was intended**. An unverified plant that produces a passing test is indistinguishable from a working guard, and it will be recorded as one.
  - FW20b planted a renamed instrument in the droit d'option guide to prove a derived citation assertion would catch prose drift. `String.replace` takes the **first** match, and the same phrase sits in the FAQ frontmatter above the prose — so the plant edited the FAQ, the prose was untouched, and the test passed. The report would have carried that pass as proof.
  - It is R133's positive-signal rule applied to the act of planting itself: *a plant I did not verify is worth exactly as much as a test that passed on its first run.*
- **The text a reader sees is derived from the thing it describes, never transcribed alongside it (R181).** The parent rule that R153, R163 and R167 each rediscovered from a different direction, stated once so the next instance is recognised rather than re-derived.
  - **R153** — copy names the **rule**, not its value: a guide's prose interpolates `{fiscal}` from `RuleSet`, and where a format cannot interpolate it says *le plafond fiscal*.
  - **R163** — prose narrating a **fixture** is tied to that fixture, including its derivatives: the Geneva worked example's 94 days and 39,16 % are computed from the cap, not typed beside it.
  - **R167** — a citation names the **instrument**, not its current file: *« Choix du système d'assurance maladie »* is the durable fact and the URL is a convenience allowed to rot.
  - The failure mode is identical in all three and in the tests that check them: a transcription is correct on the day it is written and silently wrong afterwards, with every suite green, because nothing connects the copy to the thing it is about. **A test that quotes the copy has the same defect as the copy.** FW20b's R167 assertion typed the form's name, and the repair was to read it out of the guide's own `droitOptionForm` claim — rename it in frontmatter and the test follows; type a variant into the prose and it fails.
  - It also decides what to do when a copy guard is inconvenient. FW20b's first fix for R126 flagging *"droit d'option"* in a spec title was to write the apostrophe as a `\u` escape — which leaves the duplication intact and hides it from the scanner. **Deriving is the fix; escaping is evasion.**
- **A check runs after the thing it checks for can exist (R182).** **Order is part of a guard's specification.** Any check whose subject is produced by a later step in the same chain is misplaced by construction — it moves after that step, or it runs twice.
  - **This is a new defect class, and it is not the one FW17–FW20 kept finding.** Those were guards verifying the absence of the wrong thing. These verify the RIGHT thing at the WRONG MOMENT, and no assertion can see it because each guard is individually, correctly true.
  - Three instances, all in FW20b: `tests/unit/meta/distdir-leaks.test.ts` runs inside `pnpm test`, which the gate runs BEFORE `test:visual` — so the leak a visual run creates is invisible to the gate run that created it, and is caught only by the next task. A baseline was regenerated against a half-edited tree, rewriting 69 images to certify a defect that had been identified but not yet removed (PARK-15). A plant was recorded as planted without checking it had landed (R180).
  - **The leak detector moves after `test:visual`, or runs twice, and the gate is audited for others.**
- **The site footer and the document footer carry different strings (R183).** SPEC §12 item 6 specifies *"each entry carries a server recording timestamp"* for **the document**, where it is always true — every entry in an exported dossier is timestamped. SPEC §17.6 put the same `$legal-01` token in the **site** footer, where the same sentence is a claim about a product state.
  - Two surfaces, two strings, and only one of them is conditional. **The document's stays verbatim and unconditional.** The site's drops the clause until `trackerExists`.
  - It supersedes FW20b's fix, which made the single shared string conditional (PARK-14). That was right about the defect and wrong about the remedy: one constant rendered on two surfaces has to be true on both, and the honest answer is two constants rather than a branch — R165's lifted-copy rule, arriving on a legal string.
- **A hand-written type declaration for a local module is generated or asserted, never argued (R185).** Either the module is typed directly (`allowJs` / `checkJs`), or a test imports both and asserts the declaration's exported names match the implementation's. **A comment explaining why divergence is tolerable is not a mechanism.**
  - `scripts/gate-selection.d.mts` is the module TypeScript actually reads, and its header predicted its own drift: *"a hand-written declaration is a second description of one module and can disagree with it"*, arguing the drift was safe because the test exercises the real module at runtime.
  - **The argument covered a declaration being WRONG, not one being INCOMPLETE.** An omitted export is not a type that disagrees — it is a compile error on correct code, landing on whoever adds the *next* export rather than whoever forgot the last one. `RUNTIME_SUITES` had been missing since `test:runtime` became selectable; nothing noticed because no test imported it, and R182's `LATE_SUITES` then cost three wrong diagnoses — a stale `tsbuildinfo`, the `@/` alias, a duplicate file — before the real cause.
  - It is R154 once removed: **the declaration asserted its own safety and nothing verified delivery.** A comment reasoned about the wrong failure mode, which is exactly what a comment does and a test cannot.
- **A regeneration prints what it photographed, not only what it produced (R184).** `scripts/visual.mjs` prints the commit it built from and whether the tree was dirty.
  - *"Which baselines changed"* is a claim about **output**; *"what was photographed"* is a claim about **input**. PARK-15 exists because only the second would have caught a run whose tree changed underneath it — R135's three requirements all held, and the assumption R135 does not state is that the tree being photographed is the tree you mean to photograph.
- **A test names a role, never a coincidence (R171).** Where a spec means *the server under test*, *the current year*, *the configured threshold*, it reads that from the source of truth — never from a literal that happens to match today. Literals are permitted only where the value **is** the assertion: a codepoint, a published figure, a fixture's expected output.
  - Three instances produced it. `ORIGIN = 'http://localhost:3000'` stood in for *the server we hit*, was accidentally correct while nothing moved, and the moment the port changed it reclassified our own chunks as third-party requests — **the analytics spec asserting the inverse of its own intent**. The other two are R163's typed derivatives and the hand-kept 320 dp route list that fell four articles behind.
- **The engine reproduces the Geneva fixtures exactly**, including their rounding — 39,16 % and 4,16 %. If a fixture fails, nothing ships, and a fixture that will not pass is a **question**, never a code change.
- **Timestamps are server-assigned.** No API path accepts a client `recordedAt`. `EntryEvent` is append-only.
- **The app never records a day by itself.** Detection proposes; the user's tap creates the entry.
- **No coordinate is ever stored, logged or transmitted.** Country is determined on-device against a bundled border polygon and the fix is discarded. The API rejects any payload carrying one.
- **No map, no live location dot, no movement timeline**, anywhere.
- **Never claim more than the record supports.** *Déclaré, enregistré, horodaté* — never *certifié, attesté, conforme*.
- **SPEC §20 "Ask first" items stop and ask.** Any runtime dependency in `calc-engine`; any change to a constant, a rounding rule or the engine's public API; adding a token outside `DESIGN-SYSTEM.md`; raising a size budget; any third-party script. Record the ruling verbatim in the report.
- **Every session ends with a report.** `REPORT-<TASK>.txt` at the repo root, pure ASCII, committed and pushed, in the format the session prompt specifies. The session is not done until it exists.

## Commands

All from `web/`. There is no root `package.json` and no pnpm workspace (SPEC D1).

```
pnpm install
pnpm dev · pnpm build · pnpm start
pnpm typecheck · pnpm lint          # eslint + stylelint
pnpm test · pnpm test:e2e
pnpm size · pnpm lighthouse
```

Engine tests: `pnpm exec vitest run tests/unit/calc-engine`. They live outside `lib/calc-engine` because the engine fence forbids every non-relative import inside it, and a co-located test would have to import `vitest`.

Budgets (R2): GATE A total first-load JS ≤ 125 KiB per public route; GATE B feature delta ≤ 25 KiB over the recorded framework baseline. Fonts and CSS are reported separately and never counted against a JS gate.
