THE TWO-VARIANT STRATEGY (a device constraint, recorded for the next session)
-----------------------------------------------------------------------------
On a PHYSICAL phone the two things this task needs pull opposite ways:
  - the server (the enable consent PATCH, A1) needs the app to reach the local container. The DEBUG
    variant hardcodes the emulator host 10.0.2.2, which does not resolve on a physical phone; only the
    AUDIT variant honours -PfrontalierHost=127.0.0.1 + `adb reverse tcp:3000` (the an-device-d4 recipe).
  - reading/seeding the Room DB and shared_prefs (A4 seed, A6 DB, A2 tally) needs run-as, which works
    only on a DEBUGGABLE build. The audit variant (release-derived) is NOT debuggable.
RESOLUTION (fail-safe, no code change): enable on AUDIT (real consent PATCH + startSampling enqueues the
worker), then `install -r` the DEBUG apk over it. Both are debug-SIGNED, so install -r preserves app data
(mode cache, the enqueued worker, the Room DB, perms); WorkManager reschedules the periodic worker on the
debug launch (verified via jobscheduler). The result is the real enable AND a debuggable build to read
from. The handoff's "debug APK" wording was for the no-server legs (A3/A6); the server legs needed audit.
