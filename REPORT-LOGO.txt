DECISIONS (conservative, R156 - advisor was not consulted per the prompt)
--------------------------------------------------------------------------------
DECISION 1 - no web manifest existed.
  The prompt says "find the existing web manifest ... and wire these"; there was
  none. The icon-192/512/maskable PNGs exist only to be referenced by a
  manifest, so leaving them unreferenced would be a half-install. Conservative
  resolution: create a MINIMAL app/manifest.ts (name + icons + start_url only -
  no colour literal, no display/standalone PWA behaviour), which wires the icons
  exactly as asked without claiming any app behaviour the task did not install.

DECISION 2 - app/icon.svg updated to the new mark.
  app/icon.svg is Next's favicon convention and was the placeholder glyph. Left
  as-is, Next would keep emitting <link rel=icon href=/icon.svg> for the OLD
  mark alongside the new /favicon.svg link, so the tab could still show the
  placeholder. Replaced its content with the kit rail mark (no gradient; keeps
  no-gradients.test green) so both the convention icon and the explicit link
  resolve to the new logo. Not deleted: no-gradients.test asserts it exists.

DECISION 3 - header lockup is an <img>, name kept as visually-hidden text, and
  two shell tests updated.
  The lockup is a two-tone brand image, so it cannot be inlined (that would put
  #173B63 in a .tsx). It is referenced by file via <img alt="">; the link keeps
  aria-label=homeLabel so the accessible name is unchanged. APP_NAME is kept in
  the DOM as a u-visually-hidden <span>, so the "product name as text" guarantee
  and its test stay GREEN unchanged (SEO/AT keep the text; only the visible
  rendering became the lockup).
  Two tests in PublicShell.test.tsx encoded the superseded placeholder design
  and were updated to the new reality (the task explicitly replaces the
  placeholder mark):
    - "hides the mark ... from assistive technology": asserted an inline <a svg>
      with aria-hidden; now asserts the <a img> brand mark is decorative (alt="")
      - same guarantee (name not announced twice), new implementation.
    - "sets the wordmark from its own R70 pair": asserted .name used the
      --type-wordmark-* type pair; the styled text name is gone with the text it
      styled, so it now asserts .lockup is sized from a size token (height
      var(--size-icon-lg), width auto). The --type-wordmark-* tokens are
      consequently unused (see NOTICED).

DECISION 4 - footer lockup is decorative, not a link.
  A second home link in the footer would add a duplicate destination to every
  page's header/footer link census (e2e/routing.spec.ts). The footer lockup is a
  decorative <img alt=""> above the columns; the footer bg is --colour-surface
  (light), so logo-lockup.svg (not the -dark variant) is correct. logo-lockup-dark
  is therefore not used.

DECISION 5 - Wordmark.tsx retained on disk.
  no-gradients.test and PublicShell.test both read Wordmark.tsx from disk (it
  guards that the rejected flag-logo file was never reached for). Deleting it
  would mean editing two meta tests; it is cheaper and safer to retain the file
  and merely drop its import. It is unrendered now.
