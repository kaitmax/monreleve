SUMMARY
--------------------------------------------------------------------
The product is Mon Releve. The legal entity is filled, the domain is
recorded, and 111 files changed across one commit.

THE RENAME WAS NOT THE HARD PART. "frontalier" is the French common noun
for the reader this product is built for, and the copy uses it correctly
dozens of times - "le statut de frontalier lui-meme", "les regles du
teletravail frontalier". SPEC 14 also freezes it into permanent URLs:
/calculateur-teletravail-frontalier. Thirty files contained the string
and ten occurrences were the product. A sweeping rename would have
corrupted the product's own vocabulary and 404ed every link ever shared,
and NOTHING IN THE SUITE ASSERTS A SLUG'S SPELLING.

FOUR THINGS WERE FOUND THAT A CAREFUL READING OF THE PROMPT WOULD NOT
HAVE PRODUCED:

  1. R189 names two places the service field lives. THERE WERE THREE.
     scripts/lighthouse.mjs held its own literal, so satisfying the
     ruling exactly as written would still have left every Lighthouse
     run refusing to measure.

  2. A FOURTH IDENTITY FORM, where no page renders it: EMAIL_FROM
     carried notifications.frontalier.fr, the only .fr host in the
     repository.

  3. TWO LITERALS A STRING SWEEP STRUCTURALLY CANNOT SEE - a bare
     toContain('frontalier') standing in for the wordmark, and the
     origin INSIDE A REGEX. Both surfaced at e2e, minutes in, rather
     than at typecheck.

  4. THE SHIPPED OG CARD. After the baselines were regenerated,
     public/opengraph-image.png still said "frontalier" while the
     baseline said "Mon Releve". Every link shared to Twitter or
     LinkedIn would have unfurled with the old name AND NO PAGE ON THE
     SITE WOULD HAVE LOOKED WRONG.

The fourth is the one worth keeping. It was caught by og-image.test.ts,
which R182's audit moved into test:late two sessions ago precisely
because it compares an artefact against something a LATER step produces.
It fired here on its first real opportunity, on the artefact with an
external audience.

DEVIATIONS
--------------------------------------------------------------------
1. ONE COMMIT, NOT FOUR. The prompt asks for four commits with the
   baselines regenerated in increment 4. The wordmark changes in
   increment 1, so 73 baselines go red there and stay red until
   increment 4 - three intermediate commits would each be a RED COMMIT,
   which R132 forbids outright. R189's requirement that the field and
   the guard move together is satisfied inside the single commit.

2. dataController is "KAMELEO LTD" rather than the prompt's "KAMELEO
   LTD, at the address above". The address is rendered by the same page
   two rows above, and the literal transcription would put the only
   English clause on a French legal page. The note describes who and
   where; it is not a string to print.

3. THE LEGAL FORM STAYS IN ENGLISH. "Private limited company, registered
   in England and Wales" is on a French page deliberately: a UK private
   limited company has no French equivalent, and rendering it "SARL"
   would name a different legal form. Transcribed as verified.

4. Seven fields were added to the entity, not three. The prompt asks for
   the three empty ones; the four others - incorporatedOn, hostingPhone,
   hostingWebsite, hostingRegistration - are values the prompt supplies
   and the LCEN wants the telephone, so they are rendered rather than
   held as data nobody shows.


NOTICED BUT NOT TOUCHING
--------------------------------------------------------------------
1. pnpm size DOES NOT CHECK WHICH BUILD IT IS MEASURING. It read a
   development .next left by the walkthrough and reported every public
   route 15x over budget, with eight FAIL lines and two GATE BREACH
   messages. Nothing in the output said "this is a dev build".

   It is R177's shape in the one tool whose entire output is a number:
   assert what you are measuring before you measure it. The obvious fix
   is a precondition - .next must carry a production build - and a line
   saying which was measured, which is R184 one tool over. Not touched
   because it changes a gate tool's contract.

2. FRONTALIER_RUNTIME AND FRONTALIER_PORT are untouched: 39 occurrences
   across scripts, configs and docs. Environment variable names are
   byte-constrained, so R188 PERMITS the unaccented form, and it does
   not require renaming them. Renaming would break every local command
   the operator runs and any FW28 deploy config already drafted, for no
   reader-visible gain. Raised as a question rather than swept.

3. The repository directory is still "frontier work" and the GitHub
   remote is still Frontalier. Neither is in scope and neither is
   reader-facing; the remote in particular is a URL that other things
   may reference.
