SUMMARY
====================================================================

An entry point is reachable from no import, BY DEFINITION. That is not
a gap in R218's closure - it is the closure's shape. The closure walks
outward from tests/db's own files and reaches everything they import,
and nothing imports instrumentation.ts, middleware.ts, next.config.ts
or a page. The framework invokes them. No amount of walking arrives at
a root.

So the enumeration is explicit, and it is asserted rather than listed:

  tests/unit/meta/entry-points.test.ts   9 tests, the new guard
  scripts/gate-selection.mjs             the enumeration, and two new
                                         selector rules
  scripts/gate-selection.d.mts           six new declarations (R185)
  tests/unit/meta/gate-selection.test.ts the pattern census, +2 labels

TWO MECHANISMS, AND THE SECOND IS WHAT KEEPS IT TRUE.

  app/**     DISCOVERED, by Next's filename conventions. A route added
             tomorrow is enumerated on the day it is written, with
             nobody remembering to list it. 49 entry points found.
  the root   CLOSED-WORLD. Every code file at the package root is
             either a framework entry point or a tool's config, and
             one that is NEITHER fails until somebody classifies it.

THE LIMIT IS STATED RATHER THAN HOPED. A convention Next ADDS - some
future app/**/proxy.ts - is not in APP_ENTRY_STEMS and would not be
found. The closed-world root check is what bounds that, because a new
root-level convention arrives as a new root-level FILE and fails as
unclassified. Discovery cannot help at the root: there is no
convention to walk, and the gap R246 was written for was at the root.

A SHELL COROLLARY TO R180
--------------------------------------------------------------------

A VERIFICATION STEP THAT CAN EXIT NON-ZERO FOR A LEGITIMATE RESULT
CANNOT BE CHAINED WITH &&.

`AFTER=$(grep -c ...)` takes the exit status of the substitution, and
grep -c exits 1 on a count of ZERO - which was the legitimate, expected
result of the plant. The chain stopped there, after the sed had already
run: plant applied, verification silently truncated, nothing printed.

It is R204's positive-signal problem in shell form. The command was
structured so that SUCCESS of the check and EXISTENCE of the thing
being checked shared one channel, and the value proving the plant had
worked was the value that aborted the proof.
