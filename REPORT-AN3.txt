THE FORMATTERS (AC1)
====================================================================

Unchanged from increment 1, carried here for completeness. Codepoint
assertions, not visual ones: formatPercent, formatDays, formatDate,
formatDateTime all assert exact character sequences including U+00A0,
U+202F and U+00E0, built via 0xXXXX.toChar() rather than pasted or
`\u`-escaped (this environment resolves a typed `\u` escape to the
literal character before it reaches disk - measured, not assumed).
R26's exhaustive loops ported: 10 001 and 1 001 deterministic cases.

Three Kotlin locale traps, each proven by actually switching
Locale.setDefault() rather than reasoned about:

  - String.format / NumberFormat.getInstance() default to
    Locale.getDefault(), which on a device is the user's own locale.
    Under German or Turkish locales this would emit a period where
    SPEC 6.4 requires a comma. What it would have done: silently wrong
    punctuation on a filed document, invisible on a machine set to
    French.
  - DecimalFormat's DecimalFormatSymbols must be pinned (Locale.ROOT)
    and every separator overwritten explicitly; the default symbol
    table for some locales groups with a period and marks decimals
    with a comma - the OPPOSITE of SPEC 6.4. What it would have done:
    39,16 rendered as "39.16" or grouped wrongly, indistinguishable
    from a correct render without switching the test device's locale.
  - java.time.ZoneId.of("Europe/Paris") is passed explicitly and never
    inherited from the JVM default, for the same reason. What it would
    have done: a timestamp rendered in the wrong wall clock on a device
    not set to Europe/Paris - silently, since the math still produces a
    valid-looking time.

Each trap has a test that fails when the pin is removed and passes
with it in place - LocaleTrapsTest.kt.

THE ONE CORRECTION THIS TASK MADE TO INCREMENT 4'S WORK:
MetricCopy.remaining/over had NO CALLER ANYWHERE until this task's
gallery wired them in. web/lib/fr/metrics.ts documents `threshold` as
"an already-formatted percentage - the output of formatPercent...
Passing a NUMBER here would put the formatting decision in two
places." The gallery's first draft called
`MetricCopy.over("le plafond fiscal")` - a noun phrase, not a
percentage - and the walkthrough screenshot showed "Jours au-dessus de
le plafond fiscal". The FIRST fix taught over() to elide "de le" into
"du" - passed its own test, was WRONG, and was reverted after reading
the web source: MetricCopy.kt is unchanged in substance from increment
4; the fix lives entirely at the call site, which now computes
`formatPercent(RULES.fiscalCeiling * 100.0, 0)` = "40 %", matching
SPEC 9.3's own quoted example ("jours restants avant 40 %") exactly.
See RED-GREEN LEDGER item 11 and NOTICED BUT NOT TOUCHING below for
increment 4's OWN test file, which still uses the noun-phrase form.

Also fixed this session: CopyReachabilityTest.kt's census matched only
`const val` inside an `object`, never a top-level `val`/`fun` or an
object-member `fun` - a real, structural blind spot, not merely
untested. Widened with brace-depth object-body scoping (a naive
version misread a top-level function's OWN local `val` as a false
object member, in the one file - RailCopy.kt - that mixes both shapes;
fixed before it shipped). Proven per RED-GREEN LEDGER item 10.
