R1100 - THE CAUSE, MEASURED
======================================================================================================
AGP's source (gradle-8.10.1-sources.jar, com/android/build/gradle/internal/tasks/
ExtractVersionControlInfoTask.kt), CreationAction.configure:
    val rootDir = creationConfig.services.projectInfo.rootDir
    task.gitHeadFile.set(FileUtils.join(rootDir, ".git", "HEAD"))          ... disallowChanges()
    task.gitRefsDir.set(FileUtils.join(rootDir, ".git", "refs", "heads"))  ... disallowChanges()
doTaskAction: if <rootDir>/.git does not exist -> NO_SUPPORTED_VCS_FOUND; if .git/HEAD does not
exist -> NO_VALID_GIT_FOUND; if HEAD is "ref: refs/heads/X" and the LOOSE file refs/heads/X does
not exist -> NO_VALID_GIT_FOUND (packed-refs is never read); else revision = that sha. With
vcsInfo.include unset these are written as generate_error_reason; with include = true it throws.
PackageAndroidArtifact (APK) and PerModuleBundleTask (bundle, root/META-INF/) both consume this
one artifact (InternalArtifactType.VERSION_CONTROL_INFO_FILE).

NOTICED BUT NOT TOUCHING
======================================================================================================
N1. Equality with HEAD says nothing about UNCOMMITTED changes in the tree that was built. The
    gate's R393 refuses unstaged edits to tracked files, but a plain assembleRelease/bundleRelease
    outside the gate does not, and untracked files are never refused. AGP's own mechanism has the
    same blind spot. A release build for distribution should be made from a clean tree; no rule
    says so yet (see Q2).
N2. The bundle is NOT proved. The Play upload is an .aab (bundleRelease); AGP feeds the same
    artifact into PerModuleBundleTask (root/META-INF/), so the fix should reach it, but no bundle
    was built in this session and checkReleaseVcsInfo reads only the APK.
N3. vcsInfo { include = true } would make AGP THROW instead of writing the error reason - in this
    layout it would always throw, so it is not the refusal; checkReleaseVcsInfo is.
N4. The fix depends on AGP internals: the task-name pattern and com.android.tools.idea.insights.proto
    classes on the build-script classpath. An AGP change that renames the task is caught by the
    check (planted above); one that removes the proto classes fails the build script's compilation.
N5. Every release APK built BEFORE this commit carries NO_SUPPORTED_VCS_FOUND, including the
    five C4 recorded; nothing here changes them.

N6. The refuted hypothesis is still written down (R267), and none of these is edited here (they
    are the orchestrator's records / history): relay/QUEUE-STATE.md:202 ("worktree builds carry
    no commit id ... a worktree's .git is a file"); relay/RULINGS-2026-11-11.txt:632 and :686
    ("every session builds in a worktree, so no release APK would carry its commit id");
    REPORT-AN-APK-DIFF.txt:421 and :1076 ("Every worktree-built release ..."). The measured cause
    is the Gradle root (android/) not being the git root; the parked task can close on this report.
