R430 - THE FIVE ICONS, FOR THE OPERATOR TO CHANGE
--------------------------------------------------------------------------------
All from lucide-static v1.48.0 - the SAME version the eight AN10b glyphs carry
(docs/lucide-icons.md), fetched from
https://unpkg.com/lucide-static@1.48.0/icons/<name>.svg on 2026-10-20 and
converted the way the existing set was: a 24-unit viewport, strokeWidth 2,
round cap and join, <rect rx> written out as path data. No new dependency.

  answered             Lucide glyph   drawable               version
  -------------------  -------------  ---------------------  ---------------
  En Suisse            building-2     ic_building_2.xml      v1.48.0
  Domicile             house          ic_house.xml           v1.48.0
  Mission (France)     briefcase      ic_briefcase.xml       v1.48.0
  Mission (pays tiers) plane          ic_plane.xml           v1.48.0
  Absence              calendar-x     ic_calendar_x.xml      v1.48.0

These are the prompt's own proposals, unchanged. Each is a KIND, never a
PLACE: no pin, no flag, no map (DESIGN-SYSTEM section 2, and R430 names the
same three). "En Suisse" is a workplace rather than a country; an absence is a
day struck out rather than a location at all.

SIZE: the `icon` size token, 20 dp. Size.icon is DESIGN-SYSTEM section 1's
`icon` PORTED to Kotlin, not a new value - section 1 states it twice (the R62
SIZE family "icon-sm 16 / icon 20 / icon-lg 24", and "ICONS: Lucide, 1.75 px
stroke, 20 px default"), so R77 covers the value and the R272/R285 precedent
covers ratifying an Android token. It is the same move AN-HOME made for
Size.rule. Nothing else was moved onto it: Material3's Icon still defaults to
24 dp at every existing call site.

TINT: LightColors.textPrimary, the same colour as the words beside it. R430
does not say, so this is the conservative choice and it is reversible - see
QUESTIONS.

ACCESSIBILITY: contentDescription is null on every one of them. The words sit
beside the glyph and say the same thing, and R430 requires TalkBack to read the
day once. The words are never absent - an AnswerLine carries both by
construction.

STROKE WIDTH, STATED BECAUSE IT DIFFERS FROM THE BRIEF AND THE ARITHMETIC IS
THE POINT: R430 and DESIGN-SYSTEM both say 1.75 px. Every drawable already in
res/drawable carries Lucide's own strokeWidth 2 on a 24-unit viewport. Drawn at
20 dp that renders 2 x 20/24 = 1.67 dp; drawn at Material's 24 dp default it
renders 2 dp. NEITHER figure is 1.75, at either size, anywhere in the existing
set. These five match the existing set rather than becoming a sixth convention;
making five icons differ from eighteen would be worse than the discrepancy, and
changing all of them is a design-system change this task was not asked for.
PARK-I1.

LICENCE HEADER WORDING, a deliberate difference from the existing drawables:
the AN10b headers read "(lucide-static v1.48.0, ISC/MIT)" because four of those
eight glyphs are on Lucide's Feather-derived list and carry MIT as well. NONE
of these five is on that list - Feather had `home` and `calendar`, which are
different names from `house` and `calendar-x` - so their headers read "ISC"
alone, and docs/lucide-icons.md now says so explicitly. The inconsistency is a
decision, not drift.

RecordedAnswer has rendered the status as a plain Text since AN-HOME; it has
never had a glyph. So "the existing status icons unchanged" is satisfied
vacuously, which is exactly the kind of pass this project refuses to let read
as coverage (R154). Stated plainly instead:

  - the status line is therefore words + colour, with no glyph. DESIGN-SYSTEM's
    "STATUS IS NEVER COLOUR ALONE: colour + icon + text, always" is met in its
    substance (the words differ, so colour is not carrying it alone) and not in
    its letter (there is no icon).

Adding one is a design decision with new copy implications and was NOT made
