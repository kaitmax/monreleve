--------------------------------------------------------------------------------
PARK-T1 is closed. A sign-out nobody asked for - a replayed or revoked
refresh token, a revoke-all, a refresh the server refuses, a 401 the refresh
cannot recover - now takes the person to the sign-in screen from whatever
screen is open, with a notice saying the session was closed and HOW MANY
DAYS wait on this phone, counted from the record as it renders. From there
nothing offers the voluntary sign-out or any other wipe. The exact PARK-T1
path - the dead shell's "Se deconnecter", confirmed - went RED on c4336db's
production code (the wipe ran) and is GREEN with the shell leaving instead.

The mechanism is small: SessionManager (:shared) tells its owner when, and
only when, the SERVER ends the session - its three forced clears, never the
voluntary wipe - and the process's one session records it; the shell
collects that and leaves. The forced state is derived, not stored: no
tokens, an account tag still current.

PARK-T2 is closed. On a forced sign-out the settings (every key /me
restores), the cached releve and the exports are cleared, through the
device's one LocalStore construction; the record and its tag are not. The
same account gets its settings back from /me and its releve from the server;
another account inherits none of it - including the offline releve, which
RED showed B being served from A's cache. One store is a QUESTION: the
detection file, whose loggingMode /me carries but nothing restores. Clearing
the settings would have made a latent crash reachable (a restored MAIN with
no settings); the saved destination is now reconciled as it is restored.

R522: every ending traced and tested, each crossing the forced clear its own
plant proves. An account deleted elsewhere cannot be told from a revoked
session or a corrupted token (all unknown_token or the refresh route's one
refusal), so it takes the same path and keeps the days - STOPPED, a QUESTION,
with the cost pinned: the same address signing in again is a new account
that receives them. R523: the worker settles, asks nothing more, wipes
nothing; the days go up with the sign-in or the next recorded day.
