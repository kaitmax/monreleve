R1170 - ONE ROOT, AND WHY THERE
Where: android/app/src/main/kotlin/ch/monreleve/app/ui/shell/AppRoot.kt, called as
  setContent { AppRoot { ... } }   in MainActivity.kt and CallbackActivity.kt.
Why there:
- One wrapper hosts every destination, so a screen added later is covered by being reachable, not by a
  modifier somebody remembers; the census fails on one that is not.
- At the root, windowInsetsPadding consumes the insets once; the Scaffold screens (the four tabs) do not
  pad twice - Scaffold and NavigationBar subtract consumed insets.
- In :app, not :shared: the insets are the Android window's. iOS hosts the shared screens in its own view
  controllers with its own safe areas; :shared stays untouched (no R573, no shared baseline moves).
- The set: systemBars + displayCutout. NOT the IME (see NOTICED K1): the keyboard covering a bottom button
  predates N1 and is a behaviour change outside it.
- No enableEdgeToEdge() call was added: it would change API 26-34 rendering, which nothing in this task can
  verify. Below Android 15 the window is not edge-to-edge and the reported insets are zero, so AppRoot pads
  nothing there - the same inset source Scaffold already read. That is REASONING, not S9 evidence.
- android/app/build.gradle.kts's targetSdk comment said edge-to-edge "is already handled from AN1's
  targetSdk 35" - the sentence Android Ruling 8 records as contradicted. Corrected in the same commit (R267).
