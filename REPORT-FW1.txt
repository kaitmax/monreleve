REPORT-FW1 - Scaffold, guardrails, CI (web)
===========================================================================

SUMMARY
-------
The web client now exists. web/ is a Next.js 15 App Router project on React 19
with TypeScript strict and noUncheckedIndexedAccess, the Frontier Work token
layer compiled from DESIGN-SYSTEM.md section 1 into 126 CSS custom properties,
and Inter self-hosted from @fontsource-variable/inter with tabular numerals
proven in a real browser.

The three spec boundaries are mechanical: lib/calc-engine imports nothing but
its own relative files, lib/ui/core cannot import React or any component
library, and no user-facing string can be written inline in JSX. Each fence was
proven by a planted violation and, separately, against the bypass shapes that
would otherwise have let it through silently.

Vitest and Playwright harnesses run, a first-load JS budget script measures
every route from the Next build manifests, a Lighthouse CI stub runs, the
/dev/composants workbench stub is noindex, and a GitHub Actions workflow runs
typecheck, lint, test, build, size and e2e.

Two things did not land clean and both need an operator ruling. The 100 KB
public budget is exceeded by the empty scaffold (102.1 KiB gzip on / with one
h1 on the page), so pnpm size is red by design rather than by defect. And the
final commit could not be pushed: the GitHub token in use lacks the workflow
OAuth scope, so .github/workflows/ci.yml is rejected by the remote.

ADDITIONAL FENCE VERIFICATION. A planted static import proves a rule fires; it
does not prove the fence has no hole. Each shape below was run against the
committed configuration. Nine behaviours, seven that must fail and two that
must pass:

  lib/calc-engine/scratch-engine.ts
    import Decimal from 'decimal.js'    FAILS  no-restricted-imports
    import { APP_NAME } from '../fr'    FAILS  no-restricted-imports
    import fs from 'node:fs'            FAILS  no-restricted-imports
    await import('react')               FAILS  no-restricted-syntax
    import { ok } from './scratch-ok'   PASSES (relative, as required)

  lib/ui/core/scratch-dyn.ts
    await import('react')               FAILS  no-restricted-syntax

  app/scratch-jsx.tsx
    <p>{'Bonjour'}</p>                  FAILS  react/jsx-no-literals
    <p>{`Bonjour ${nom}`}</p>           FAILS  react/jsx-no-literals
    <div className="card" data-zone="fiscal" lang="fr">   PASSES

  x 7 problems (7 errors, 0 warnings)

Three of those shapes would have defeated a naively configured fence:

  - A glob group of '*' on lib/calc-engine also restricts './types', which
    would make the engine's own seven FW3 files unimportable. The rule uses a
    negative-lookahead regex instead, so relative imports pass and bare
    packages, node: builtins, aliases and ../ escapes all fail.
  - no-restricted-imports never sees a dynamic import() or a require(), so the
    React ban in lib/ui/core - the fence AC2 actually plants a violation for -
    was defeatable by rewriting one line. no-restricted-syntax closes it.
  - react/jsx-no-literals defaults to noStrings:false, whose canonical fix is
    to wrap the string in braces, which then passes. noStrings:true is set.

stylelint, same treatment. Six must-fail shapes and six must-pass:

    background-color: rgb(247 248 250) FAILS
    border-top-left-radius: 10px      FAILS
    padding-left: 13px                FAILS
    box-shadow: 0 1px 3px rgb(...)    FAILS
    gap: 7px                          FAILS

  x 8 problems (8 errors, 0 warnings)

The shorthand and the function form matter: stylelint-declaration-strict-value
matches property names literally and defaults ignoreFunctions to true, so
"border: 1px solid #E4E7EC" and "rgb(247 248 250)" both sail past a default
configuration - and "border: 1px solid #E4E7EC" is exactly how
DESIGN-SYSTEM.md section 1 writes the card. expandShorthand is on,
ignoreFunctions is off, and the property list uses regex forms so longhands
are covered.

Font payload detail: inter-latin-wght-normal.woff2 is 48256 bytes (47.1 KiB)
and is the only file a French page fetches; inter-latin-ext-wght-normal.woff2
is 85068 bytes (83.1 KiB) and is gated behind its unicode-range. FW2's "font
subset under 60 KB" criterion is met by the latin subset at 47.1 KiB.

Method, stated because each choice moves the number across the gate on a page
containing one h1:

  1. A route's first load is its own manifest entry UNIONED with every
     ancestor layout entry. app-build-manifest.json keeps "/page" and
     "/layout" as separate keys and the page entry does not list the layout
     chunk, so reading "/page" alone under-reports every route.
  2. Each file is gzipped separately at level 9 and the sizes summed.
     Gzipping the concatenated buffer reports about 1 KB less than the browser
     receives, because the browser gets each file compressed independently.
  3. Polyfills are measured but excluded from the gate. Next serves
     polyfills-*.js with nomodule, so no browser supporting ES modules
     downloads it, and Next's own First Load JS column excludes it too.
  4. /dev/** is measured and printed but not gated. It is noindex, out of the
     sitemap, and not part of the acquisition surface that SPEC section 17
     budgets; FW2 deliberately builds a component-heavy page there.

Cross-check against an independent oracle. Next's own build output reports
First Load JS of 103 kB for /, against this script's 102.1 KiB (104550 bytes,
i.e. 104.5 kB). The two agree to within about 1.5 kB, the difference being the
layout chunk this script includes and Next's rounding. Both are over budget.

THE BUDGET IS UNREACHABLE AS SPECIFIED. The page being measured contains one
h1 and one figure. 102.1 KiB is the Next 15 App Router plus React 19 baseline:

QUESTIONS FOR THE OPERATOR
--------------------------

1. GITHUB TOKEN SCOPE - blocks the final push. The token authenticating this
   repository has scopes gist, read:org, repo. Creating or updating
   .github/workflows/ci.yml requires the workflow scope, so commits 6b07f79 and
   b4392de and this report cannot be pushed. Granting it takes one command in
   an interactive terminal:

     gh auth refresh -h github.com -s workflow

   after which git push origin main sends everything. Until then the CI file
   exists only locally, and the first CI run cannot be observed or referenced
   here as increment 6 asks. No workaround was attempted: the same scope gates
   the contents API, and rewriting history to hide the workflow commit would
   misreport the session.

2. THE 100 KB PUBLIC BUDGET IS UNREACHABLE - needs a ruling before FW2.
   Measured: 102.1 KiB gzip first-load JS on /, on a page containing one h1 and
   one figure. Next's own build output agrees (103 kB). The whole of it is the
   Next 15 App Router plus React 19 baseline: framework chunk 54.2 kB gzip,
   app-router runtime 46.5 kB gzip. No feature code is in the bundle.

   Raising a size budget is on the Ask-first list, so I have not touched it.
   pnpm size and the CI size step are red. The options, as I see them:

     a. Raise the public budget to a number the baseline can meet (roughly
        110-120 KiB leaves headroom for the calculator).
     b. Keep 100 KB and change the delivery model for public routes so the
        React runtime is not shipped at all - a real architectural decision
        that would want deciding before FW10, not after.
