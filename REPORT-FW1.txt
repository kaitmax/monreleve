REPORT-FW1 - Scaffold, guardrails, CI (web)
===========================================================================

SUMMARY
-------
The web client now exists. web/ is a Next.js 15 App Router project on React 19
with TypeScript strict and noUncheckedIndexedAccess, the Frontier Work token
layer compiled from DESIGN-SYSTEM.md section 1 into 129 CSS custom properties,
and Inter self-hosted from @fontsource-variable/inter with tabular numerals
proven in a real browser.

The three spec boundaries are mechanical: lib/calc-engine imports nothing but
its own relative files, lib/ui/core cannot import React or any component
library, and no user-facing string can be written inline in JSX. Each fence was
proven by a planted violation and, separately, against the bypass shapes that
would otherwise have let it through silently.

Vitest and Playwright harnesses run, a first-load JS budget script measures
every route from the Next build manifests, a Lighthouse CI stub runs, the
/dev/composants workbench stub is noindex, and a GitHub Actions workflow runs
typecheck, lint, test, build, e2e and size.

A review pass over the finished work found four defects in it, all now fixed
and re-proven; REVIEW PASS below records what they were, because two of them
were guardrails this report previously claimed were closed and were not.

Two things still need an operator ruling. The 100 KB public budget is exceeded
by the empty scaffold, though only by 628 bytes, so pnpm size is red by design
rather than by defect. And the last commits cannot be pushed: the GitHub token
in use lacks the workflow OAuth scope, so .github/workflows/ci.yml is rejected
by the remote.

REVIEW PASS
-----------

The finished work was audited against AC1-AC3, the Definition of Done and this
report's own claims before the session was called done. Four defects were
found in FW1's own output, and all four are fixed in commit 910c109. Two
of them were guardrails the first version of this report asserted were closed.

1. THE ENGINE FENCE WAS DEFEATED BY "./../fr". The pattern was a single
   negative lookahead, ^(?!\./), which restricts anything not starting with a
   relative marker. Prefixing an escape with "./" satisfies it:
   import { APP_NAME } from './../fr' passed lint clean, as did './x/../../fr'
   and the dynamic form. That is a one-character bypass of the boundary the
   Kotlin port depends on, and the previous report claimed "../ escapes all
   fail". Fixed by adding a second restricted pattern, (^|/)\.\.(/|$), and the
   matching ImportExpression selector.

2. BOTH IMPORT FENCES WERE SCOPED TO *.ts, NOT *.tsx. The overrides globbed
   lib/calc-engine/**/*.ts and lib/ui/core/**/*.ts. FW1.txt increment 3 says
   lib/ui/core/**; the narrowing was mine. A React component accidentally
   written in lib/ui/core carries the .tsx extension, which is the realistic
   shape of exactly the violation AC2 plants - and it passed lint, typecheck
   and build. Fixed by globbing {ts,tsx,mts,cts}.

3. THE BUDGET SCRIPT COUNTED CSS AGAINST A JS BUDGET. It summed every file in
   the manifest entry with no extension filter, so the route stylesheet was
   inside a column headed "first-load JS" and gated against a budget SPEC
   section 17 defines as JS. This inflated the number the escalation in
   QUESTION 2 rests on: / was reported at 102.1 KiB, and the correct JS-only
   figure is 100.6 KiB. The breach is real either way, but it is 628 bytes,
   not 2.1 KiB. Fixed; CSS is now measured and printed on its own column,
   ungated.

4. pnpm dev WAS NEVER RUN. AC1's first clause is "pnpm build and pnpm dev
   run". Only build was ever executed or evidenced. Fixed by running it and
   capturing the transcript, now in INCREMENT 1.

Six smaller corrections were made at the same time:

  - global.scss: -webkit-text-size-adjust restored. The increment-3 stylelint
    --fix had rewritten it to the unprefixed property, which WebKit alone does
    not implement, so the declaration was inert on iOS Safari - most of this
    audience. Recorded then as "formatting"; it was behavioural.
  - check-budgets.mjs: the dev-bucket test was a substring test, so a future
    public route named /devis or /developpement would have been silently
    excused from the gate. It is now segment-aware. Route-group segments are
    also stripped, so FW10's app/(public)/page.tsx will print as "/" rather
    than "/(public)".
  - check-budgets.mjs: it exited 0 with "All gated routes are within budget"
    when it measured zero routes. It now fails loudly instead.
  - package.json: the abandoned pnpm.ignoredBuiltDependencies block was still
    present alongside the pnpm-workspace.yaml setting that actually works.
    Two live sources of truth for one setting; the dead one is removed.
  - playwright.config.ts: reporter was 'list', which writes no
    playwright-report/ directory, so CI's upload-artifact step would have
    uploaded nothing on every run. The html reporter is added.
  - .stylelintrc.json: line-height, height, inset, top/right/bottom/left,
    flex-basis and letter-spacing added to the property list - tokens.scss
    already defines tokens for those values - and /^calc\(/ removed from
    ignoreValues, which had let calc(13px + 1px) through on a fenced property.
  - tokens.scss: $motion-toast-min/max (DESIGN-SYSTEM section 1 "TOAST ...
    3-5 s") and $size-button-border (secondary button "1 px border") were
    missing from an otherwise complete transcription. Added, taking the
    custom-property count from 126 to 129.
  - .github/workflows/ci.yml: pnpm size moved after e2e. It is knowingly red,
    and a blocking red step ahead of e2e meant CI would never have produced an
    e2e signal at all.

Exact figures for /, measured rather than back-computed from the display value:
6 JS files, 350991 bytes raw, 103028 bytes gzip level 9. The budget read as
KiB is 102400 bytes, so the breach is 628 bytes.

Font payload detail: inter-latin-wght-normal.woff2 is 48256 bytes (47.1 KiB)
and is the only file a French page fetches - confirmed from the Lighthouse
network trace, which shows the latin file requested and the latin-ext file not.
inter-latin-ext-wght-normal.woff2 is 85068 bytes (83.1 KiB) and is gated behind
its unicode-range. FW2's "font subset under 60 KB" criterion is met by the
latin subset at 47.1 KiB.

Method, stated because each choice moves the number across the gate on a page
containing one h1:

  1. A route's first load is its own manifest entry UNIONED with every
     ancestor layout entry. app-build-manifest.json keeps "/page" and
     "/layout" as separate keys and the page entry does not list the layout
     chunk, so reading "/page" alone under-reports every route.
  2. Only .js is counted. The manifests also list the route stylesheet, and
     SPEC section 17 budgets first-load JS. CSS is measured and printed in its
     own column.
  3. Each file is gzipped separately at level 9 and the sizes summed.
     Gzipping the concatenated buffer reports about 1 KB less than the browser
     receives, because the browser gets each file compressed independently.
  4. Polyfills are measured but excluded from the gate. Next serves
     polyfills-*.js with nomodule, so no browser supporting ES modules
     downloads it, and Next's own First Load JS column excludes it too.
  5. /dev/** is measured and printed but not gated, on a segment-aware test.
     It is noindex, out of the sitemap, and not part of the acquisition
     surface SPEC section 17 budgets; FW2 deliberately builds a
     component-heavy page there.

Cross-check against an independent oracle. Next's own build output reports
First Load JS of 103 kB for /. This script measures 103028 bytes, i.e. 103.0
kB. They agree exactly. (Before the review pass, when CSS was still being
counted, the two disagreed by 1.6 kB and this report attributed the gap to the
layout chunk; the layout chunk is 169 bytes and the stylesheet was 1483.)

THE BUDGET IS EXCEEDED, BY 628 BYTES. The page being measured contains one h1
and one figure. 100.6 KiB is the Next 15 App Router plus React 19 baseline: the
framework chunk is 54.2 kB gzip and the app-router runtime chunk is 46.5 kB
gzip, and neither is reducible by configuration. There is no feature code in
the bundle at all. This is the FW2 escalation arriving one task early, and
PHASE-1.md routes exactly this case back to the operator. Raising a size budget
is on the SPEC section 20 Ask-first list, so the budget has been left at the
spec value and pnpm size is red. See QUESTIONS FOR THE OPERATOR item 2.

1. SPEC section 5 lists FIVE ESLint-enforced import boundaries. FW1.txt
   increment 3 enumerates three, and those three are implemented. Boundary 3,
   "lib/ui imports types from calc-engine, never logic; it computes nothing",
   is NOT fenced by anything. The first opportunity to violate it is FW8, where
   a component types a result prop, and it becomes likely at FW11/FW12 where
   importing the engine into a presentational component is precisely the
   mistake the boundary exists to stop. The rule that would close it is a
   no-restricted-imports entry on lib/ui/** permitting lib/calc-engine in type
   position only. Not added: increment 3 names three fences and adding a
   fourth is a decision, not an implementation detail. Boundary 5 (_zones.scss
   generated from zones.ts) is FW6's by name.

2. THE HOMEPAGE WILL COLLIDE AT FW10. FW1 put the minimal / page at
   app/page.tsx. SPEC section 5 places the homepage at app/(public)/page.tsx
   under app/(public)/layout.tsx. Next treats those as two parallel routes
   resolving to the same path and fails the build, so FW10 must relocate or
   delete app/page.tsx rather than simply adding the route group. Flagging it
   because the failure surfaces as an opaque Next build error, not as a spec
   conflict. The budget script already normalises route-group segments, so it
   is ready for that move.

3. USER-FACING PROPS ARE NOT FENCED. react/jsx-no-literals is configured with
   ignoreProps:true, as FW1.txt requires, so className, data-* and lang stay
   writable. The cost is that placeholder, alt, title and aria-label are
   unfenced. Nothing in the codebase has one yet; FW9 introduces the first real
   form.

4. METADATA STRINGS ARE NOT FENCED EITHER. export const metadata is a plain
   object, not JSX, so jsx-no-literals never visits it. The workbench title is
   imported from lib/fr by convention, not by enforcement.

5. THE TOKEN FENCE CAN BE LAUNDERED THROUGH A SASS VARIABLE OR A CUSTOM
   PROPERTY. stylelint-declaration-strict-value inspects the value side of a
   matched property only. Writing $card-border: #e4e7ec in some other .scss
   and then using $card-border passes, because the declaration that created it
   is never checked, and a --my-token: 13px declaration matches none of the
   configured property patterns. So "nothing outside tokens.scss declares a raw
   colour, radius or spacing" is enforced for direct declarations but not for
   indirect ones. Closing it means forbidding $-variable and custom-property
   declarations outside tokens.scss, which is a rule FW1 was not asked for.
   Worth deciding before FW6 writes the first generated stylesheet.

6. RAW VALUES IN REACT INLINE style={{...}} OBJECTS ARE NOT FENCED. stylelint
   only sees .scss, and no ESLint rule covers the style prop, so
   style={{ color: '#ff0000', padding: '13px' }} passes everything. The fix
   would be react/forbid-dom-props on the style prop, which is a decision about
   how components are allowed to be written, not an implementation detail.
   Related: the lint glob is {app,lib}/**/*.scss, so a .css file, or a
   stylesheet outside app/ and lib/, would not be linted.

QUESTIONS FOR THE OPERATOR

1. GITHUB TOKEN SCOPE - blocks the final push. The token authenticating this
   repository has scopes gist, read:org, repo. Creating or updating
   .github/workflows/ci.yml requires the workflow scope, so the CI commit and
   everything after it cannot be pushed. Granting it takes one command in an
   interactive terminal:

     gh auth refresh -h github.com -s workflow

   after which git push origin main sends everything. Until then the CI file
   exists only locally, and the first CI run cannot be observed or referenced
   here as increment 6 asks. No workaround was attempted: the same scope gates
   the contents API, and rewriting history to hide the workflow commit would
   misreport the session.

2. THE 100 KB PUBLIC BUDGET IS EXCEEDED BY 628 BYTES - needs a ruling before
   FW2. Measured: 100.6 KiB gzip first-load JS on /, against a 100.0 KiB
   budget, on a page containing one h1 and one figure. Next's own build output
   agrees exactly (103.0 kB both ways). The whole of it is the Next 15 App
   Router plus React 19 baseline: framework chunk 54.2 kB gzip, app-router
   runtime 46.5 kB gzip. No feature code is in the bundle.

   Raising a size budget is on the Ask-first list, so I have not touched it.
   pnpm size and the CI size step are red. The options, as I see them:

     a. Raise the public budget to a number the baseline can meet. Note the
        margin is now 628 bytes, so even 101 KiB clears today - but it would
        leave essentially no headroom for the calculator, so a number chosen
        deliberately (110-120 KiB) is better than one chosen to go green.
     b. Keep 100 KB and change the delivery model for public routes so the
        React runtime is not shipped at all - a real architectural decision
        that would want deciding before FW10, not after.
     c. Keep 100 KB, accept a red gate until FW2 measures the component-heavy
        page, and decide then with more evidence.

   yours to rule on. Whatever is decided should be recorded verbatim in the
