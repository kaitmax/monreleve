All six jobs green.

a. NODE PARITY (R27) - deferred since FW6
   job 105740568856 (node 22), job 105740568932 (node 24)

     format parity on v22.23.2 (ICU 78.2, CLDR 48.0)
       11 codepoint cases and 10001 exhaustive values: all identical
     format parity on v24.20.0 (ICU 78.3, CLDR 48.0)
       11 codepoint cases and 10001 exhaustive values: all identical

   THE ICU VERSIONS DIFFER - 78.2 against 78.3 - AND THAT IS WHAT
   MAKES THIS A RESULT. Had both runtimes shipped the same ICU build,
   this would have compared one library to itself through two wrappers
   and learned nothing. Two builds, 10 001 exhaustive values,
   identical output.

   R6's formatters normalise Intl output because ICU has emitted
   different separator codepoints across versions. That claim has been
   asserted since June and had never been tested on a second runtime.
   It is now PROVEN AGAINST AN ACTUAL VERSION DIFFERENCE rather than
   resting on a documented hazard. Three months deferred, eight
   seconds to settle.

b. test:runtime (R81) - unrun FW10 to FW15, rarely since
   job 105740408919 - 9 passed (44.2s)

   The refusal behaviours, each named by its test:
     /api/health reports degraded, and names what is missing
     the home page omits its canonical rather than pointing at
       localhost
     no localhost URL reaches the rendered head at all
     the site still SERVES - degraded is not broken
     liveness stays 200 while readiness refuses - the same process,
       the same moment
     /api/ready names the failing check and the variable to set
     the readiness refusal is not cached

   A guard that existed, was correct, and had never executed. This
   closes the longest-standing gap in the project.

c. THE VISUAL SUITE ON A RUNNER - never run
   job 105740408253 - 108 passed (1.2m)

THE MEASUREMENT I REACHED FOR FIRST WAS VACUOUS, and that is the
finding in this section.

  /timing  ->  {"UBUNTU": ... "total_ms": 0}   on the SKIPPED run
  /timing  ->  {"UBUNTU": ... "total_ms": 0}   on the FULL run

Billable minutes read ZERO FOR BOTH, because a public repository is
not billed at all. The number is identical for a run that allocated
nothing and a run that held six machines for five and a half minutes.
Had this report cited total_ms as its zero-cost proof it would have
cited a figure that CANNOT DISTINGUISH THE TWO STATES - the same shape
as R169's foreign health check answering 200, and as R213's
never-executed check reporting no failures. An absence assertion
satisfied by absence, one more time, on the metric that looked most
like money.

WHAT ACTUALLY PROVES IT, three independent signals:

  1. runner_name is NONE ALLOCATED on all five jobs.
     On the full run it names six machines - GitHub Actions 1000000931
     through 1000000936. NO MACHINE WAS EVER ASSIGNED is what zero cost
     means; a billing figure is a downstream consequence of it.
  2. Wall clock 2 SECONDS against 5m33s.
     22:14:35 to 22:14:37, versus 19:52:00 to 19:57:33.
  3. FIVE jobs, not six.
     The matrix job is listed UNEXPANDED - its name still carries the
     literal matrix expression - because `if:` is evaluated BEFORE
     matrix expansion. The two runtimes were never enumerated, so the
     skip happened upstream of the fan-out rather than five times
     inside it.

RESTORATION IS PROVEN BY THE NEXT PUSH rather than asserted here: the
commit carrying this section runs with CI_FULL back on, and both
directions are therefore observed. A switch demonstrated in one
direction only is half a switch - the same reason R196's constraints
prove acceptance as well as rejection.

COST OF THE PROOF: one 2-second run, no runner, nothing billable even

DEVIATIONS
--------------------------------------------------------------------
1. THE REPOSITORY WAS ALREADY PUBLIC when the session began. The
   prompt reads as though the session opens the window; the operator
   had opened it. The R212 audit and the history check were therefore
   done on an already-exposed repository rather than before exposure -
   which is why they were done FIRST, before anything was enabled.

2. A NEW VARIABLE, CI_FULL, rather than reusing CI_OCTOBER. Reusing
   it would have conflated two different decisions - "the public
   window is open" and "the October allowance has arrived" - in one
   flag, and the revert would then have had to remember which one it
   was undoing.

NOTICED BUT NOT TOUCHING
--------------------------------------------------------------------
1. ACTIONS DEPRECATION WARNINGS on every job: actions/checkout@v4,
   setup-node@v4, upload-artifact@v4 and pnpm/action-setup@v4 target
   Node 20, which is deprecated and being forced to Node 24. They
   still work. Bumping them is a change to CI on the day CI is being
   used to verify something else, which is the wrong day.

2. ubuntu-latest MIGRATES TO UBUNTU 26 on 19 October 2026, per the
   runner's own annotation. That is a base-image change under the
   visual job, and R37's container pinning means the VISUAL suite is
   insulated from it - but the other four jobs are not.

3. A FOREIGN DEV SERVER WAS RUNNING ON THIS MACHINE throughout the
   gate - four node processes belonging to Downloads/tizicorp, another
   repository entirely, including a Next dev server holding port 3200.
   NOT KILLED: R179 authorises a harness to kill the tree IT spawned,
   and this is not one. It held no port of ours - 3000 and 3101 were
   both clear - so R169 never fired, correctly. Recorded because the
   FW20 defect began exactly here, with somebody else's Next server on
   this machine, and what made it harmless this time was R170 giving
   our suite a port of its own.

4. THE FIRST GATE RUN CRASHED TWO VITEST WORKERS - exit 134 (SIGABRT)
   and 2147483651 - with 1.8 GB free of 15.8 GB, the foreign dev
   server holding 1.2 GB of it. NOT A TEST FAILURE: 2527 of 2577
   passed and two files never started. The re-run passed 142 files and
   2577 tests, WHICH ARE THE RUNNER'S EXACT COUNTS. Worth one line
   because a crashed worker and a red test look alike in a tail, and
   only one of them is evidence about the product.

5. FW23 IS INCOMPLETE. Increments 4, 5 and 6 - the read path, the
   frozen contract document, the walkthrough - are FW23's session, not
