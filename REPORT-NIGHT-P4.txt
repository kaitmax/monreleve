OPEN QUESTIONS
--------------------------------------------------------------------
Q66 (FW21). Entry_detectedKind_when_detected is enforced in the
     FORWARD direction only: a DETECTED_CONFIRMED or
     DETECTED_CORRECTED row must carry detectedKind. The reverse - a
     MANUAL row must carry none - follows from the definitions but
     SPEC does not state it. I did not enforce it because enforcing
     only what is stated can never refuse a row SPEC permits, while
     enforcing what is merely implied can. A ruling before FW23
     freezes the API contract would be worth having; if yes, it is
     one line in a migration against an empty table.

Q67 (FW21). EntryEvent has no foreign key on entryId, matching SPEC
     8, so a deleted Entry leaves events pointing at an id that no
     longer resolves. That is deliberate - the trail must outlive
     the row it records - and FW23's delete path and FW24's dossier
     both depend on it. Confirming the intent.
