R1404 - WHAT THE OPERATOR SHOULD KNOW
================================================================================
1. WHAT CFBundleDevelopmentRegion IS, per Apple's documentation
   (developer.apple.com/documentation/bundleresources/information-property-list/cfbundledevelopmentregion, read
   2026-11-23): "The default language and region for the bundle, as a language ID. The system uses this key as the
   language if it can't locate a resource for the user's preferred language."
   Bundle.developmentLocalization "corresponds to the value in the CFBundleDevelopmentRegion key"
   (developer.apple.com/documentation/foundation/bundle/developmentlocalization).
   This app has no .lproj at all, so for an English-device user French is the fallback.
2. WHAT AN ENGLISH-DEVICE USER SEES, MEASURED (R1403(b)): on an en-US simulator, the in-app share sheet's "Copy" is
   "Copier", while the rest of the sheet stays English. The app's own text is French regardless, since Compose draws
   it from the app's French constants. Before this change, the same user saw "Copy".
3. THE APP STORE'S LANGUAGE LIST.
   - Apple DTS, Apple Developer Forums thread 813504 (Jan 2026, DTS Engineer, Worldwide Developer Relations): "The
     value of the `Languages` field in the App Store is determined by the existence of `.lproj` folders in your app
     bundle."
   - App Store Connect Help ("Localize app information") separates that list from the listing's metadata languages,
     which the operator chooses in App Store Connect.
   - This change adds NO .lproj, so it adds nothing that list reads.
   - What the list shows for a bundle with no .lproj at all is NOT documented in what I found. Apple names no case
     for it, and no upload was made. I did not guess.
   - If the store must list "French", the documented route is a fr.lproj in the bundle. That is a new mechanism R1403
     excludes: QUESTION 2.
4. InMemorySettingsStore, a test fake, STILL SHIPS in the Release framework.
   - It is public in commonMain because :app's unit tests (ThresholdAlertPresenceTest, SessionEndSeamTest,
     ParametresWirePinTest) need it, and they cannot see :shared's commonTest.
   - The mechanism that would end this is a shared test-fixtures source: :shared publishing a test-only source set
     (a KMP equivalent of Gradle's java-test-fixtures, for example a dedicated test-support module or source set
     that :app's testImplementation depends on).
   - That is a build change, so it is named and not built.
   - It is harmless at run time (nothing in the app constructs it) but it is shipped code.
