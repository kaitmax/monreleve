INCREMENT 0 - R327: RegisterCoverageTest WIRED INTO gate:clone (ONE definition)
====================================================================
THE DEFECT: RegisterCoverageTest (every PARK-/PARKAN- id a REPORT cites must have a
"## <id> -" heading in parking.md) ran ONLY in the Android suite
(:app:testDebugUnitTest). gate:clone - the PUSH gate - does not run the Android
suite, so a report commit citing a heading-less id could red :app:gate AFTER it had
already left this machine through a push. AN-NEXT-2's PARKAN-37/38 did exactly that,
and main went red between tasks.

THE FIX (R206 - ONE definition, not a copy that can drift): the check is a
REPOSITORY-WIDE DOCUMENT check (parking.md + the repo-root reports, no Android code
but a path helper), so its LOGIC moved to one place both gates invoke as a
subprocess - web/scripts/register-coverage.mjs (pure Node, fs only):
  - gate:clone runs it FIRST (cheapest signal, before install), against the clone's
    own copy of the script and documents;
  - RegisterCoverageTest.kt now shells out to the SAME script via ProcessBuilder, so
    :app:gate still enforces it. node is on PATH wherever :app:gate runs (this
    machine; the ubuntu-latest Android CI job, where it is preinstalled); a missing
    node fails LOUDLY (R133), never a silent pass.
Gradle-in-the-clone was REJECTED (conservative, R156): the clone has no
local.properties and ANDROID_HOME is unset, and a cold Android compile is far too
heavy and fragile for a push gate. A Node definition both gates share is the single
source with no language-boundary drift.

PROVEN (R178/R180): node web/scripts/register-coverage.mjs is GREEN on HEAD (28
cited ids across 73 reports), RED BY NAME on a planted heading-less id (written here
as PARKAN-NNN so this report does not itself cite a real-looking id: the check named
