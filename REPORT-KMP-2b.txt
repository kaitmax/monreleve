R395 - WHICH migrate() DOES ROOM 2.7.2 CALL? CITED, NOT REDONE
--------------------------------------------------------------------------------
ANSWER: the CONNECTION form, migrate(connection: SQLiteConnection).
CONSEQUENCE: ONE body serves Android and iOS. Not a stop; no second copy of the
SQL anywhere.

R419 says this is re-established only "if REPORT-KMP-2 did not already answer it".
It did, from two independent directions, on this same phone:

  DOCUMENTARY, from Room 2.7.2's Migration.android.kt in this build's own Gradle
  cache: migrate(connection) is ALWAYS the entry point, and the Support overload
  runs only as a DELEGATION out of it - and only while the migration has not
  itself overridden the connection form. The KDoc says it outright: "This function
  is only called when Room is configured without a driver. If a driver is set
  using [setDriver], then only the version that receives a [SQLiteConnection] is
  called."

  ON THE DEVICE: a probe planted in both overrides of MIGRATION_1_2 logged ONE
  entry into the connection form, holding a SupportSQLiteConnection, same thread,
  same millisecond. Probe removed.

RE-READ HERE, because a quotation is worth less than the file. The commonMain
Migration.kt declares exactly one member - open fun migrate(connection:
SQLiteConnection) - and androidx.sqlite's commonMain SQLite.kt defines
public fun SQLiteConnection.execSQL(sql: String) { prepare(sql).use { it.step() } }.
Those two are the entire API the moved bodies use.
