CANONICAL AND HREFLANG - A LOOP OVER THE REGISTRY

  The root's is the bare origin with no trailing slash, which is how Next

R52 PROOF
================================================================================

RENDERED WHILE EMPTY, ABSENT WHEN COMPLETE, AND EXACT IN BETWEEN (R84).

lib/content/legal-entity.ts ships nine constants, every one an empty string. A
default of "frontalier SAS" would be a claim about a company that does not
exist, on the page where a reader is most entitled to rely on it - and it
would be INVISIBLE, because a plausible name reads as filled in. Whitespace
counts as missing: a single space satisfies a length check and prints as
nothing, which is the exact failure R52 exists to prevent.

Each page declares the constants it consumes, and each is rendered exactly
once. That is a constraint on the prose, not an accident: the sections after
an identity block say "l'editeur" rather than repeating the name, which is
ordinary legal French and also what keeps the count meaningful.

  /mentions-legales  7  legalName legalForm address registrationNumber
                        contactEmail hostingProvider hostingAddress
  /confidentialite   6  dataController address dpoContact contactEmail
                        hostingProvider hostingAddress
  /cgu               3  legalName address contactEmail

  dataController and dpoContact are absent from mentions legales on purpose -
  they belong to the privacy notice, and the publication director is named as
  "the legal representative of the editor", which needs no constant and avoids
  conflating two different legal roles. legalName and legalForm are absent
  from the privacy notice for the mirror reason.

MEASURED IN THE PRERENDERED HTML, not only in jsdom:
  .next/server/app/mentions-legales.html   7 placeholders in the markup
  .next/server/app/confidentialite.html    6 placeholders in the markup
  (the same counts appear again in the embedded RSC payload, which is data
  rather than rendered DOM - worth knowing before anyone greps the file and
  reports double)

THE TEST IS ONE SHARED HELPER, tests/unit/pages/placeholder-census.tsx, not a
transcription per page: three copies of the same count would drift, and the
one that drifted would be the page nobody reread. Per page it asserts
  - the declaration names only real entity fields, each once, enough of them
  - all empty   -> exactly N placeholders
  - all filled  -> exactly 0
  - for EACH declared field, everything else filled -> exactly 1
  - every filled value actually appears, so a page that printed nothing at
    all could not score zero and pass
The per-field sweep is what makes the declaration honest: without it, a
declaration could name a value the page never prints, or the prose could
repeat one, and the all-empty total would still add up by accident.

A NOTE ON THE PAGE ITSELF: while anything is open, each page renders one
sentence saying that unfilled mentions appear in brackets and will be
completed before public service. It describes the placeholder without
reproducing the string, which would have added to the count. It disappears
when isComplete() is true.

The ten new page baselines contain the placeholders deliberately. Filling the
constants in IS a visual change, and the diff will be the record of it.

DEVIATIONS
================================================================================

D1. THE TRAILING-SLASH REDIRECT IS 308, NOT 301.
    The prompt says "trailingSlash false with 301 from the slashed form". Next
    emits 308 for slash normalisation, and `permanent: true` in a redirects()
    rule emits 308 as well - there is no configuration that produces a literal
    301; it would have to come from the reverse proxy. 308 is the permanent
    redirect that additionally preserves the request method, and search
    engines treat the two identically. The Playwright assertion accepts either
    and carries the explanation. Say the word if you want the 301 forced at
    the proxy in FW28 and I will add it to that task.

D2. THE SITEMAP IS app/sitemap.xml/route.ts, NOT app/sitemap.ts.
    Carried from the R81 work rather than new. The `sitemap.ts` convention
    returns a data structure that Next serialises; there is no way to return a
    status code from it, so R81's 503 is not expressible. Same URL, by a
    mechanism that can refuse.

D3. THE PLACEHOLDER IS "[A COMPLETER]", UNACCENTED.
    Exactly as the prompt writes it, twice. Correct French would be
    [A COMPLETER] with its accents; the relay files are pure ASCII by mandate,
    so the prompt's spelling is not evidence either way. It is one constant in
    lib/fr/legal.ts. Question below.

D4. THE LEGAL PROSE USES ORDINARY SPACES BEFORE COLONS AND SEMICOLONS.
    Correct French typography wants U+00A0 there. tests/unit/fr/copy-
    codepoints.test.ts is a registry of which whitespace codepoints the copy
    contains and fails when the SET CHANGES, precisely so introducing one is a
    deliberate edit with an audit of the assertions that compare against that
    string. I did not spend FW10's budget on a typography pass across four new
    copy files; the registry is the mechanism that will make it deliberate.
    The headings-plus-paragraphs structure avoids most in-sentence colons.

D5. TWO NESTED tsconfig.json FILES ADDED, app/ and tests/.
    Each sets only "jsx": "react-jsx". Not a dependency, not a token, not a
    budget - and the mechanism was already established and measured in
    lib/ui/react/tsconfig.json: the root must stay "preserve" because Next
    rewrites that field on every build, and oxc reads the nearest tsconfig to
    the file it compiles. Rendering a page component in a unit test made oxc
    compile .tsx under app/ and tests/ for the first time, and without these
    it fails to PARSE rather than fails an assertion. pnpm typecheck and next
    build are untouched: tsc is invoked with the root config and does not
    consult nested ones.

D6. THE CONTRAST AUDIT'S SCOPE WIDENED TO app/, EXCEPT app/dev/.
    R76 fixed how the audit resolves a background and said no exemption list
    exists; it did not fix which files it reads, and it read lib/ui/react only.
    That was right when app/ held one placeholder page and no colour. The 404
    paints its links --colour-brand on the page surface - exactly the pairing
    the audit exists to measure - and it would have gone unmeasured. Scope
    matches R74's reading of R60. The discovery is asserted so the widening
    cannot silently find nothing.

D7. pnpm size NOW MEASURES THE REAL 404.
    The root 404 is TWO manifest entries - /_not-found/page for the internal
    catch-all and /not-found for the component in app/not-found.tsx - and only
    the first ends in "/page", so the loop never saw the component's chunks. It
    reported 100,8 KiB with a 0,2 KiB feature delta on a route that ships
    PublicShell: a route passing its gate on a number that was not its
    payload, which is worse than a breach because nothing looks wrong. Found
    by comparing chunk counts, 5 against 7.

D8. pnpm test:coverage ADDED TO MY LOCAL GATE.
