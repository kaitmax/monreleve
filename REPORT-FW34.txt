--- R326: pnpm size measures ONLY the build that ships -------------
Commit 72d3fb9.

THE DEFECT. check-budgets.mjs read `.next` with no idea what build it
was, so it measured, with equal confidence, a `next dev` build or a
production build with the dev routes compiled in (FRONTALIER_DEV_ROUTES=1,
which R129 shows is ~1.6 KiB high on the calculator). FW33's reported
"+1.9 KiB" was the second kind (REPORT-FW33b: the real cost was +0.4).

THE FIX (one home, R206):
  - scripts/size-marker.mjs: SIZE_MARKER_FILE, writeSizeMarker,
    readSizeMarker, and shippingMarkerRefusal (a PURE decision).
  - scripts/size-marker.d.mts: types so next.config.ts (strict tsconfig,
    allowJs off) can import the writer. R185 - auto-covered by
    tests/unit/meta/declaration-parity.test.ts, which walks every .d.mts
    beside a .mjs and asserts the value exports match in both directions.
  - next.config.ts: a webpack `done` hook stamps EVERY build and EVERY
    `next dev` (plain webpack dev here, not Turbopack - checked) with a
    marker recording the phase and the dev-routes flag. In the config,
    not a post-build script, because `next dev` never exits (an `&&`
    after it never runs) and a prior build's marker would otherwise
    vouch for a dev server that overwrote `.next` around it.
  - check-budgets.mjs: the SHIPPING measurement (no --dev) refuses, BY
    NAME, a missing marker / a `next dev` build / a dev-routes build.
    --dev is exempt by design (size:dev MEASURES .next-dev-routes to gate
    GATE W / GATE I).
  - tests/unit/meta/size-marker.test.ts: the refusal, both directions
    (R154), plus the marker round-trip.

PLANT PROOF (R180 - real builds; each marker confirmed on disk before
reading the result):
  clean `pnpm build`          -> marker {phase:build, devRoutes:false}
                                 -> pnpm size: "All gated routes pass"
  `next dev` on port 3190     -> marker {phase:dev, devRoutes:false}
                                 -> pnpm size REFUSED, exit 1:
     "pnpm size measured a `next dev` build in .next/, not the build
      that ships (ruling R326). ..."
  FRONTALIER_DEV_ROUTES=1        -> marker {phase:build, devRoutes:true}
    next build (into .next)      -> pnpm size REFUSED, exit 1:
     "pnpm size measured a production build with the dev routes compiled
      in (FRONTALIER_DEV_ROUTES=1) in .next/, not the build that ships
      (ruling R326). ... this is the FW33 "+1.9 KiB" defect. ..."
  reverted (clean `pnpm build`) -> marker {phase:build, devRoutes:false}
                                 -> pnpm size: "All gated routes pass"
  The next-dev process tree was killed and port 3190 verified free (R179).

SAFE FOR THE EXISTING GATES (checked, not assumed): `size` is not in
gate:changed; and both `pnpm gate` and gate:clone run `pnpm build`
IMMEDIATELY before `pnpm size` (gate-clone.mjs line ~583: "build before
size because size reads .next", and e2e/visual are skipped in a clone),
so size always reads a clean shipping build there and keeps passing.
