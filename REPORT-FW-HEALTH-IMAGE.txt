R931. THE FIX NAMES A ROLE, NOT A COINCIDENCE
---------------------------------------------
web/e2e/home.spec.ts:
- SERVING_DECLARATION = 'FRONTALIER_SERVER_IS_SERVING' (line 189).
  declaredServing() is true only when that variable is '1'.
- :195, "/api/health reports ok, and its runtime marker is the one its
  launcher declared":
  - status 200, status ok and reasons [], as before;
  - `runtime` toBe(declaredServing()), with both values in the message.
- :211, "/api/ready is 200 and ready, and evaluates the database exactly
  when serving":
  - reads `runtime` from /api/health: the role, from the server itself
    (R171);
  - asserts 200, ready true, and every ok !== false;
  - asserts the database check is listed and `ok` toBe(serving ? true :
    null). Not serving: listed with ok null. Serving: evaluated, ok true,
    and ready true.

web/scripts/container-e2e.mjs:
- sets FRONTALIER_SERVER_IS_SERVING=1 in the suite's environment, beside
  FRONTALIER_SERVER_IS_OURS. No other launcher sets it.
- The NON_SERVING_TITLE exclusion is removed: the constant, the
  --grep-invert, its printed lines and its comment. The comment block now
  says why. The /dev/** exclusion is unchanged.

Why a declaration, and not a branch on `runtime` alone:
- A spec that branches on `runtime` cannot also assert `runtime`.
- The host run would then pass with a marked server exactly as quietly as
  the image does, which would loosen it.
- With the declaration:
  - the host run still asserts runtime false, as before;
  - the container run asserts runtime true;
  - each fails if its server is in the other state (R196's shape).
