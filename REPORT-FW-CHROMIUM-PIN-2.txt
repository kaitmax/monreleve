    .47 -> .73   FW-CHROMIUM-PIN, RED measured 2026-11-02
    .73 -> .79   this task; C1 measured .73 gone on 2026-11-11
  Debian keeps only the newest point release in bookworm-security. Each
  new Chromium build there turns every uncached build into the R249
  refusal until a one-line commit lands.
  The options, NOT chosen here:
    (a) keep the exact pin and bump it on each release. That is the current
        practice: a renderer change is always a commit, at the cost of a
        build outage between Debian's release and the bump.
    (b) a scheduled read-only check (`apt-cache madison` against the ARG)
        that announces the drift before a deploy meets it, keeping (a).
    (c) install the pinned .deb from snapshot.debian.org. The version
        stays installable, but security fixes arrive only when someone
        bumps it.
    (d) a base image with Chromium preinstalled, built once and referenced
        by digest. Stable and fast, but it needs a registry and its own
        refresh process.
    (e) verify the major only and record the resolved version in the image.
        This relaxes R249's "the browser cannot move without a commit".
    (f) render with Playwright's own Chromium, pinned through the lockfile
        (playwright-core), instead of Debian's package. The pin moves into
        the lockfile, at the cost of image size and of R229's packaging
        decision.
