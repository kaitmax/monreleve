R343 - THE PARAMETER, AND WHY IT IS THE SHAPE IT IS
====================================================================
THE NAME IS `rythme`. Lowercase, French, a whole word where the word
is short - the style of `methode` and `decompte` beside it. Not in
schema.test.ts's forbidden-words list, and it could not be: see the
privacy note below.

DOCUMENTED AS FROZEN in SPEC-frontalier-web.md section 9.4, in the
table with the nine, plus a paragraph stating that it is R343, frozen
from its first deploy, that it does not map into TeleworkInput, that
it repeats, and that absent means no projection.

THE RENAME TEST R343 ASKS FOR IS IN TWO PLACES, because there are two
things to freeze:
  tests/unit/params/schema.test.ts  - the NAME, in the ten-element
      frozen list, with a comment saying what editing it costs.
  tests/unit/params/rhythm.test.ts  - what its VALUES mean, as an
      exact map: lu/ma/me/je/ve. A rename of a CODE breaks exactly as
      many links as a rename of the parameter.

IT REPEATS, AND THE FIRST DESIGN DID NOT - A CORRECTION MADE BEFORE
ANYTHING SHIPPED. The first version was positional: `rythme=sdsds`,
five characters, one per weekday, three symbols so a day could be
teleworked, worked in Switzerland, or not worked at all. It was
shorter, more expressive, matched the Android rhythm model exactly,
and it CANNOT BE PRODUCED BY AN HTML FORM. A checkbox submits its own
name and value or nothing; five of them cannot agree on one string
without JavaScript to assemble it. R346 requires the rhythm to work
with scripting OFF, so a format that only works hydrated is the wrong
format, and it was replaced with `?rythme=ma&rythme=je` - five
checkboxes, one name, the browser building the query itself.

WHAT THAT COSTS, STATED RATHER THAN GLOSSED: the URL carries telework
days only. The web question is binary per day, so a day left
unchecked is simply not a telework day and the URL cannot say whether
it was worked in Switzerland or not worked at all. THAT IS LOSSLESS
FOR THE RATE, and the shared fixture establishes it rather than
reasoning: `les-jours-suisses-ne-bougent-pas-le-taux` imagines five
Swiss days and expects the rate NOT to move. The Rhythm TYPE still
carries both kinds because the fixture does; it is the URL that is
narrower than the type, which is the right way round.

THE PRIVACY ARGUMENT WAS EXTENDED, NOT BROKEN. schema.ts rested it on
"every param maps to a field of TeleworkInput, which holds days, a
rate, a canton and a method - there is nowhere for a name to go".
`rythme` is the first parameter that does not map there. Widening
TeleworkInput to make that sentence true again would have been wrong
twice over: it is the engine's public API and SPEC 20 makes changing
it an ask-first item. So ParamSpec.field is now EngineField |
ForecastField, and schema.test.ts asserts BOTH halves - every param
maps into one of the two sets, AND the forecast set contains exactly
`rythme`. The replacement is narrower than what it replaces: the
value space is five legal codes, and a format with five legal values
cannot carry an identity whatever anybody types.

EVERY LINK SHARED BEFORE TODAY IS UNCHANGED, asserted literally:
`expect(encode(BASE).toString()).toBe('canton=GE&tt=84')`. encode
takes the rhythm as an optional second argument defaulting to none,
so the share row, the island and the result page were not touched and
still produce the byte-identical string.

====================================================================
THE DATE FUNCTION
====================================================================
lib/forecast/imagined.ts - imaginedEntriesToYearEnd(rhythm, today,
taxYear). One plain function, no clock of its own, no arithmetic
beyond a calendar walk.

IT RETURNS ENTRY ROWS, NOT A COUNT, and that is the design decision
worth recording. A count would be smaller and would be a second
engine: the denominator, the proration, the half-day arithmetic and
the mission cap all live in toTeleworkInput and calc-engine, and a
function returning "24 telework days" invites its caller to divide by
240 - FW12's defect, R340's rule. Rows go in the same door recorded
ones do, which is also what makes the shared fixture checkable step
for step rather than at the final percentage.

UTC THROUGHOUT for the walk, for the reason the codec's own date
arithmetic gives: a Date advanced by local days crosses a DST
boundary twice a year and silently gains or loses one.

CLAMPED AT BOTH ENDS to the tax year, so a link opened in a later
year cannot imagine days outside the year whose denominator is being
used.

THE GUARDS THAT FIRED ON ONE PARAMETER
====================================================================
Adding `rythme` tripped three independent guards, in three different
suites, each written by a different task. None was a false alarm and
none was a bumped number: each needed a decision about whether the new
parameter was covered.

1. tests/unit/params/schema.test.ts - THE FROZEN LIST.
   "is exactly the nine, in the order SPEC 9.4 tabulates them" went
   red naming `rythme`, which is what schema.ts's own header promises:
   "tests/unit/params/schema.test.ts asserts the list element by
   element so the asking is unavoidable." Updated to ten, with the
   rename-cost comment R343 asks for.

2. tests/unit/params/schema.test.ts - THE PRIVACY PROOF.
   "maps every param to a field of TeleworkInput and nothing else"
   went red because `rythme` maps to `rhythm`. This is the one that
   mattered: the honest repair was to widen the PROOF, not the type.
   See the R343 section above.

3. e2e/og.spec.ts - THE SOCIAL-CARD LEAK CHECK.
   "a nine-param URL and the bare path return the same bytes" asserts
   the OpenGraph card is byte-identical whether or not the URL carries
   a calculation - a user's exposure must not leak into a social
   thread. It pins PARAM_NAMES.length, and its comment says why: "The
   nine names are read from the schema, so a tenth parameter added to
   the product arrives here rather than being remembered."
   IT ARRIVED. The fixture now carries every parameter including two
   repeated `rythme` values, and the count is still PINNED rather than
   loosened to ">= 1" - a rhythm says which days of the week somebody
   is at home, which is as much a disclosure as a day count, and a new
   disclosure must not reach a social card without somebody deciding
   it is covered.

WHAT THIS SAYS ABOUT THE DESIGN. A parameter is not one fact in one
file. It is a frozen name, a value vocabulary, a privacy claim, a
leak surface and a form control, and three separate suites held three
of those. None of them could have been found by reading the diff.
