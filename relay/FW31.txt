CONTEXT
====================================================================
FW31 ONLY: F-WRITE, F-CI and F-CONTRACT.

WHAT HAPPENED, so the fix addresses the condition and not the line.
POST /api/v1/entries returns 500 and writes zero rows on a production
build. The cause takes both halves: the Prisma client memoises only
when NODE_ENV is not production, and the Proxy passes itself as
Reflect.get's receiver, so $transaction opens on one client and
resolves its internals against others. Application code is correct.
Second consequence: about four pools leak per request and roughly
twenty-five requests exhaust the database - and a request with a
garbage bearer token leaks them too, so no account is needed.

THE CONDITION IS THE FINDING. Dev and test memoise; gate:clone skips
the container suites; CI's container job has never passed;
container-e2e.mjs never POSTs an entry; and no e2e spec touches this
route BY DESIGN, since D14 removed the signed-in web area. Five
layers, each individually reasonable, and the intersection is a hole
the size of the product's main use case.

Read: REPORT-FW30.txt, docs/audit-adversarial.md, web/lib/db/client.ts,
web/lib/entries/write.ts, docs/api-v1.md, scripts/gate-clone.mjs.
