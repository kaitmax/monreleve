====================================================================
CONTEXT
====================================================================
AN14a ONLY: turn on R8 and harden the release build, without any Play
account, signing key or reachable domain.

THE AUDIT'S POINT, RESTATED. The release build has never been
minified - isMinifyEnabled is false and the R8 rules are a
placeholder - so the classic ways a Kotlin app works in debug and
breaks on release have not had a chance to appear yet: a serialised
class whose fields R8 renamed, an enum constant renamed on the wire, a
class reached only by reflection and removed. This task makes them
appear, on purpose, and fixes each one with the narrowest rule that
works.

The release build still cannot reach a real server: monreleve.ch does
not resolve. So the minified code is exercised through the AUDIT
variant AN-AUDIT committed - release's build configuration with the
debug network settings - which now inherits R8. The report says
exactly how that variant differs from the true release, so the claim
is never larger than the evidence.
