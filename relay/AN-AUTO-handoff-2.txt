WHY A1-full / A4 / A7 NEED A SERVER, and the one setup that gives it
-------------------------------------------------------------------
Turning auto detection ON records consent through /api/v1/me (R315/FW26). setAutoDetection(true) only flips the
toggle and calls startSampling AFTER the PATCH returns 2xx. With a dummy injected session and no reachable
server the PATCH is NetworkError, so the toggle stays off and the REAL sampler never schedules - which is why
A1's enable/sampling, A2 (a full window of real sampling), A4 (near-border from real tallies) and A7 (state on
the live auto screens) all need a signed-in app talking to a real server.

THE RIG (reuse android/scripts/an-audit-walkthrough.mjs's recipe verbatim): it provisions the monreleve:write
container + a scratch pg DB, obtains a REAL session from /api/v1/auth/callback, and injects it with
SessionInjectionActivity so every screen talks to the real server. Build the image if absent (web side). Then:
  1. Grant perms for the window run (the disclosure/prompt flow is already proven; for the window just grant):
       adb -s 232bcd8c300c7ece shell pm grant ch.monreleve.app android.permission.ACCESS_FINE_LOCATION
       adb -s 232bcd8c300c7ece shell pm grant ch.monreleve.app android.permission.ACCESS_BACKGROUND_LOCATION
  2. Keep awake:  adb -s 232bcd8c300c7ece shell svc power stayon usb
  3. In Parametres, toggle " Detection automatique (beta) " ON, pass the disclosure + both prompts (grant
     "Toujours autoriser" for background). The PATCH now succeeds -> toggle ON -> DetectionScheduling.startSampling
     enqueues the periodic SamplingWorker. Toggle OFF -> stopSampling cancels it at once (A1's off half).
