CONTEXT
====================================================================
AN0 ONLY: install the Android skills, vet them against this
project's rulings, and record what conflicts.

It writes no app code. AN1 is the scaffold.

WHY IT IS ITS OWN TASK. A skill is instructions entering the agent's
context and shaping what it builds. This project has 257 rulings,
several of which deliberately contradict generic Android practice -
Material components themed rather than defaulted (D37), no radius
outside the token set (R8, R62), French-only copy from one module
(R155, R206), RED before GREEN (the ordering rule), no toast for a
pending sync (R176's family), no gamification. Reading the eight
skills against those BEFORE any code exists is cheaper than
discovering a conflict at AN9 in a component that already shipped.

SOURCE: https://github.com/android/skills - official, Google,
Apache-2.0. It ships a .claude-plugin directory, so it installs as a
Claude Code plugin; the Android CLI's `android skills add --project=.`
is the alternative. Either is fine; record which was used and where
the files landed.

Read: docs/PHASE-4-GUIDE.md section 14 (what the Android series
inherits), SPEC 5 (the android/ layout), SPEC 11 (the app), SPEC 13
(detection), DESIGN-SYSTEM.md sections 1, 2 and 4, CLAUDE.md,
prompts/design-frontier/FD4, FD5, FD6, FD7, FD9 if present (R231 - if
they are not in the repository, say so and use SPEC).
