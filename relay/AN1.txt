CONTEXT
====================================================================
AN1 ONLY: the Android project's scaffold, its theme, its fences, its
CI, and - the part that decides the next fourteen tasks - THE
INSTRUMENT.

THE INSTRUMENT IS WHY THIS TASK MATTERS MOST. On the web, a person
looking at a rendered thing found what no gate could, in every task
for six tasks running: a page serving with no CSS, /sources
miscounting itself by six, fifty unstyled anchors below the fold of
every crop, eight defects in the PDF with two visible only in
greyscale, an export shipping enum tokens to a French reader. On
Android there is no page to fetch and no server to curl. A Compose
screen exists only on a device.

So the instrument has to be built: a headless emulator, a screenshot
captured with adb, and a PNG the agent can open. IF IT IS NOT WIRED
HERE IT WILL BE SKIPPED IN EVERY LATER TASK, with a plausible excuse
each time. Treat it as an acceptance criterion, not a convenience.

Read: SPEC 5 (the android/ layout), SPEC 11 (the app), SPEC 20;
DESIGN-SYSTEM.md sections 1, 2 and 4 - the token block is normative;
docs/android-skills.md (the conflicts and the extracted notes);
docs/PHASE-4-GUIDE.md section 14. If prompts/design-frontier/FD4,
FD5, FD6, FD7 or FD9 are absent, say so (R231) and build from SPEC
and DESIGN-SYSTEM, which are the named authority.

ACCEPTANCE CRITERIA
====================================================================
AC1. The app builds and launches to a placeholder Aujourd'hui with
     FrontierTheme applied: Inter rendering with tabular numerals on
     a figure, the canvas at its token colour, and no Material
     default shape or elevation anywhere. Proven by a SCREENSHOT the
     session captured and looked at, not by the build succeeding.
AC2. THE INSTRUMENT WORKS END TO END: a script starts a headless
     emulator, installs the debug build, drives it, captures a PNG,
     and the session OPENS THAT PNG and describes what is on it. The
     report names the file and says what was seen. A harness that
     produces an image nobody looked at is not the instrument.
AC3. Every fence fails on a planted violation and each plant is
     VERIFIED TO HAVE LANDED (R180), adversarially (R7): a
     RoundedCornerShape(10.dp), a raw Color(0xFF...), a raw spacing
     literal, a String literal in a composable, an android.* import
     inside calc/, a coordinate type outside detection/ - and for
     each, one evasion attempt (a constant indirection, an alternate
     file extension, a re-export).

====================================================================
INCREMENT 4 - THE INSTRUMENT (AC2)
====================================================================
This is the increment the series depends on. Build it properly.

- scripts/emulator.sh (or .mjs): create or reuse a named AVD, start
  it headless (-no-window -no-audio -no-boot-anim), adb wait-for-
  device plus a boot-completed poll, and FAIL LOUDLY with a named
  reason if it does not come up. R133 - a script that silently
  proceeds without a device produces screenshots of nothing.
- scripts/screenshot.sh: adb exec-out screencap -p > <path>, with
  the device serial asserted and the file's size checked non-zero.
  R233 - the measurement reports whether it observed its subject; a
  0-byte PNG must fail, not pass.
- ORPHAN DISCIPLINE (R98/R105/R179): the harness kills the emulator
  it started, asserts no stale emulator or adb server before
  starting, and names what it found. Four concurrency classes have
  bitten this project; a long-lived emulator is the fifth.
- A walkthrough helper: install the debug APK, launch the activity,
  optionally drive it with adb shell input, capture, and print the
  path.
- THEN USE IT: capture Aujourd'hui, OPEN THE PNG, and describe what
  is on it in the report - the greeting, the canvas colour, whether
  the figure renders with tabular numerals, whether anything has a
  Material shadow. AC1 is proven here, by looking.
- Commit: "AN1: the emulator and screenshot instrument". Push.
