2. RECORDING SEVERAL DAYS AT ONCE - A NEW FEATURE
====================================================================
This adds behaviour, so it is built test-first like any feature.

ENTERING SELECTION
  - An explicit "Selectionner plusieurs jours" button. A long press on
    a day may also start it, but never as the only way - nobody finds a
    long press unaided.
  - Tap days to toggle them; tap a first day then a last day to select
    the range between. A holiday week is two taps, and is the most
    common case.
  - Future days cannot be selected, as single-day editing refuses them
    today. Whatever single-day editing cannot record, selection cannot
    either.
  - Each selected cell shows it is selected in a way that does not rely
    on colour alone, and TalkBack announces "selectionne" and the count.
  - At 200 percent the calendar is a list (R271); selection works there
    too, with a checkbox per row.

THE ACTION PANEL, in the space now empty at the bottom of the screen
  - Shows how many days are selected, the choices - En Suisse,
    Domicile, Mission en France, Mission dans un pays tiers, Absent -
    and Annuler. Absent asks for its reason, once, for all the days.
  - Applies to WHOLE DAYS. Splitting a day into halves stays in the
    single-day editor.

ONE CONFIRMATION BEFORE ANYTHING IS WRITTEN (D16)
  - It lists the days, and the choice.
  - If some selected days already have a value: "N jours deja
    renseignes seront modifies".
  - If some are older than the late threshold: "Ces jours seront
    marques "saisie tardive" dans votre releve". This is true - the
    server flags them - so the person learns it before confirming,
    not from the releve. THE THRESHOLD COMES FROM THE ONE SHARED VALUE
    (R286); never a 7 typed here.
  - Confirm writes; Annuler writes nothing.

WHAT IS WRITTEN
  - ONE MUTATION PER DAY, each with its own clientMutationId born at
    the confirmation tap, each tagged with the account (R303), each
    with clientClaimedAt = the confirmation tap (R275). A bulk entry is
    exactly the same records as entering the days one by one - nothing
    in the record says "bulk", because nothing about the evidence is
    different.
  - Sync batches them within the server's batch limit (the named
    constant); a month never needs more than one or two batches. The
    server refuses two items for the same day in one batch, and a
    selection never contains a day twice - assert it.
  - A rejected item is isolated as R296 already does.
