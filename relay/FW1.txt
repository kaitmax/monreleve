STANDING PROTOCOL (identical in every FW / AN prompt)
====================================================================
1. SESSION SCOPE. This session implements FW1 and nothing else. Do
   not start FW2. Do not "prepare" future tasks.

2. INCREMENT CYCLE. Work in the ordered increments below. For each:
   implement -> test -> verify -> commit -> push, then move on. The
   project must build and existing tests must pass after EVERY
   increment. Never accumulate more than ~100 lines uncommitted.

3. COMMIT ONLY ON GREEN. A commit happens only when pnpm typecheck,
   pnpm lint, pnpm test and pnpm build all pass on the increment. If
   an increment cannot reach green, do not commit it: revert or
   stash, and report the blocker. A red commit is a bounce.

4. COMMITS. One logical change per commit. Message format:
   "FW1: <increment title>". Push after each increment and capture
   the push output for the report.

5. SIMPLICITY FIRST. The naive, obviously-correct version. No
   abstraction before the third use case demands it. No config
   machinery for a single consumer.

6. TEST-FIRST. New behavior: failing test before the code (RED),
   minimum to pass (GREEN), refactor with tests green. A test that
   passes on its first run proves nothing - for pivotal tests, show
   the failing run in the report. Bug and bounce fixes: reproduction
   test that FAILS before the fix and PASSES after. Assert outcomes,
   never internal call sequences. Prefer real implementations; mock
   only at fixed boundaries (email, push, external network, the
   clock via injection). Use the repo's own scripts; focused runs in
   the loop, the full suite once before the report. Never re-run a
   command on unchanged code for reassurance.

7. UI DISCIPLINE. DESIGN-SYSTEM.md is the design system: Inter with
   tabular numerals, the token radii {4,8,12,14,16,20,24,999}, the
   listed colours, Lucide icons, no shadows on cards. Every radius,
   colour and spacing is a token. Composition over configuration;
   split any component past ~200 lines; every screen ships loading,
   empty and error states; semantic elements first; one h1 per page.
   French strings live only in lib/fr.

8. SCOPE DISCIPLINE. Touch only what FW1 requires. Do not clean up,
   refactor, or "improve while you are here". Anything noticed
   outside scope goes in the report under NOTICED BUT NOT TOUCHING.

9. QUESTIONS. On any spec ambiguity or anything on the spec section
   20 "Ask first" list: PAUSE the increment, ask the operator, and
   record the ruling VERBATIM in the report. Never decide
   unilaterally. Never deviate silently.

10. EXIT ARTIFACT. End by writing REPORT-FW1.txt at the repo root,
    committed and pushed, in the format at the bottom of this prompt.
    The session is not done until the report exists with its push
    proof.

Pure ASCII applies to relay prompts and reports, NOT to code. Source
files may contain accented French where the product requires it.

TASK FW1 - SCAFFOLD, GUARDRAILS, CI (web)
====================================================================
Objective (tasks/todo.md): initialise the Next.js 15 App Router
project under web/ with TypeScript strict, pnpm, the Frontier Work
token layer as Sass + CSS custom properties, self-hosted Inter
(variable, tabular numerals enabled), lucide-react, and the lint
guardrails that make the spec's boundaries mechanical; plus test
harnesses, the web size budget, the /dev/composants workbench stub,
and CI.

Acceptance criteria (restated; the report must prove each):
AC1. pnpm build and pnpm dev run; the token layer compiles to CSS
     custom properties; Inter served same-origin (latin + latin-ext)
     with tabular numerals verified on a rendered figure.
AC2. Each guardrail demonstrably fails lint/CI on a planted
     violation - raw hex, raw radius or spacing off the token set,
     React import in lib/ui/core, inline French string in JSX -
     proofs captured, violations removed. The history contains only
     clean states.
AC3. pnpm size runs with the web budget configured (public routes
     <= 100 KB gzipped first-load JS) even though routes are near
     empty.

TDD note for this task: FW1 is configuration, the one case where
behavior-level TDD does not apply. Its RED steps are the planted
violations in increment 3 and the smoke tests in increment 4 (run
each once against a deliberately wrong expectation to confirm it can
fail, then fix the expectation). Behavior-level RED/GREEN is
mandatory from FW3 onward.

--------------------------------------------------------------------
INCREMENT 2 - Token layer and Inter
--------------------------------------------------------------------
- lib/ui/core/styles/tokens.scss: every value from DESIGN-SYSTEM.md
  section 1 as Sass variables AND as CSS custom properties on :root
  (colour.*, space.*, radius.*, type.*). Nothing outside this file
  declares a raw colour, radius or spacing.
- lib/ui/core/styles/global.scss: reset, canvas #F7F8FA via the
  token, base type, imported from the root layout. Sass configured
  in Next.
- Inter: @fontsource-variable/inter, subsets latin + latin-ext,
  self-hosted, preloaded. A utility class or mixin enabling
  font-feature-settings: "tnum" for figures.
- Verify: pnpm build. Then prove: render / (next start + curl or the
  build output) and grep output and .next assets for
  "fonts.googleapis" and "gstatic" - both absent; the font file
  resolves under the app's own origin. Render one figure with the
  tabular class and confirm the feature setting in computed style
  (Playwright arrives in increment 4; a note that this check is
  completed then is acceptable).
- Commit: "FW1: Frontier token layer, global styles, self-hosted
  Inter". Push.

--------------------------------------------------------------------
INCREMENT 3 - Lint guardrails (the heart of FW1)
--------------------------------------------------------------------
ESLint flat config with per-directory overrides:
  (a) lib/calc-engine/**: the engine imports NOTHING outside its own
      directory - no-restricted-imports (or import plugin equivalent)
      forbidding all bare module imports and any lib/* or app/* path.
      Relative imports inside lib/calc-engine remain allowed.
  (b) lib/ui/core/**: forbid react, react-dom, and any UI component
      library. Pure TS + SCSS only.
  (c) app/** and lib/ui/react/**: react/jsx-no-literals so user-facing
      strings cannot be written inline - they are imported from
      lib/fr. Technical attributes (className, data-*, aria via
      imported strings) must not be blocked.
stylelint with stylelint-declaration-strict-value on: color,
background-color, border-color, fill, stroke, border-radius,
font-size, margin, padding, gap (and their longhands). Only Sass
$tokens / var(--token) / keywords are accepted; raw hex and raw px
literals are rejected.

PROOF SEQUENCE (output goes in the report, never in the history):
  1. Plant four violations in scratch locations:
     - a raw hex colour in a .scss file,
     - a raw border-radius: 10px in a .scss file,
     - import React from 'react' inside lib/ui/core/,
     - a literal French string inside a JSX element under app/.
  2. Run pnpm lint. Capture the four failures (trimmed output).
  3. Remove all four. Run pnpm lint clean.
- Commit (clean state only): "FW1: ESLint boundary rules and
  stylelint token guardrails". Push.
