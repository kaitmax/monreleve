THE PRODUCT RULES (the orchestrator's, conservative, because SPEC says only one sentence):
R1110. THE FLAG. A new PUBLIC, unauthenticated, cacheable-for-minutes route under /api/v1 (name it
    by the house conventions - read web/app/api/v1/*) answers the minimum supported Android
    versionCode. Its source is ONE server setting read at request time (e.g. an env var with a
    named constant for its key); UNSET, EMPTY OR MALFORMED MEANS NO MINIMUM (the route says so
    explicitly, never a guessed number) - so the mechanism ships INERT and the operator turns it
    on in Coolify by setting a value. No database table (no schema change). The response names
    the product the way /api/health does, so a client can tell the right server answered (R169).
    Tests first: unset, empty, malformed, a valid value, and the route never needs a session.
R1111. THE APP. On launch and when returning to the foreground, :shared asks the route. If the
    app's versionCode is BELOW a valid minimum, a full-screen, plain update screen replaces the
    app: a title, one sentence, and one button that opens the Play listing of ch.monreleve.app
    (market:// with the https Play URL as fallback). Nothing else is reachable from it.
    FAIL OPEN: unreachable server, a non-200, a foreign or malformed answer, or no minimum ->
    the app works exactly as today, with no screen and no delay to first paint beyond what the
    request already costs (it must not block startup on the network). The decision is a pure
    function in :shared commonMain, tested on every branch above (RED first).
