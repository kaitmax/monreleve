====================================================================
2. THE CALCULATION - ONE CONTRACT FOR WEB AND APP
====================================================================
- THE IMAGINED YEAR: the days the person entered so far, plus, for every
  working day AFTER TODAY to 31 December (Europe/Paris, R28), the
  rhythm's kind. Public holidays and leave are NOT deducted: on the
  240-day basis that overstates telework, so the projection warns
  early, never late - and the page says so.
- The date logic lives in ONE plain, unit-tested TypeScript function,
  then the existing aggregation and engine run as for any calculation.
- SHARED FIXTURE: fixtures/forecast-cases.json. If AN-FORECAST created
  it, CONSUME IT - never fork it; add cases if needed, and both the web
  and the Android suites must pass. If it does not exist yet, CREATE it
  in the same shape AN-FORECAST describes (a rhythm, a date, the
  expected count of imagined days, the engine's rate). A one-digit plant
  in it must fail the web suite (and the Android one, if it consumes
  it) - planted, verified, reverted (R180, R283).
- "TODAY" IS THE DAY THE PAGE IS REQUESTED. The result must never be
  served from a cache with an old date: render it per request, and
  state the date on the page ("Projection au <date>"). A shared link
  opened later recalculates for that day. Test it with a fixed clock.
