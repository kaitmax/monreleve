0. R334 - A SESSION NEVER DESTROYS WHAT IT DID NOT CREATE
====================================================================
R334 (new, and it binds this session from its first command). A SESSION
    NEVER DELETES, OVERWRITES OR RESETS ANYTHING IT DID NOT CREATE.
    Two incidents prompted it: FW-VERIFY deleted relay/AN-LINKS.txt, an
    operator file, because it was untracked and "not this task's"; and
    the Android chain's orchestrator ran `git checkout -f` and wiped a
    running agent's uncommitted work. So:
      - an untracked or unexpected file is REPORTED, never removed;
      - every agent works in its OWN git worktree; nothing destructive -
        checkout -f, reset --hard, clean, rm - runs in a directory another
        agent may be using, and never without git status first;
      - A REPORT STATES ONLY WHAT HAS HAPPENED. AN-ONBOARD's report said
        "merged to main" before the merge, because its agent hit the
        session limit first. Write "pending merge" until it is true.

WORKTREE CLAUSE ON THIS MACHINE (deviation, recorded by AN-ONBOARD-2).
    Git worktrees are infeasible here: the Windows path-length limit
    truncates nested .claude/worktrees/ paths (documented). So sessions
    run on a BRANCH in the main directory instead, and tasks run
    SEQUENTIALLY - never two agents at once. That satisfies R334's intent
    (no agent clobbers another's live work) by scheduling rather than by
    worktree isolation; the destructive-command and report-only clauses
    above still bind as written.

THE PARKING RULE FOR THIS PHASE (R156, with a phase-specific file)
====================================================================
The operator is asleep. An open question does NOT stop the task.
  (1) Take the CONSERVATIVE, REVERSIBLE option - the one that claims
      less, ships less, and can be changed tomorrow without a
      migration, a 301, a published correction, or an app release.
  (2) Record it in Phase4parking.md at the repo root, entries
      numbered PARK4-<n>, in the format below.
  (3) Continue.

PARK: a missing credential (build the seam, fake the transport, park
  the real one); a missing external artefact (assetlinks fingerprints,
  a licence, a domain); copy wording; a token value already in a
  brief; a test's strictness; a component shape; a hedge-versus-state
  decision on an unverified claim.

DO NOT PARK - STOP AND WRITE THE REPORT:
  - anything PERMANENT: an /api/v1 route shape, a field name, a
    database column needing a migration, a slug, an anchor;
  - anything that would PUBLISH A FALSE OR UNSOURCED CLAIM, including
    a privacy claim on /confidentialite that the code does not make
    true;
  - a gate, budget or threshold change;
  - a new runtime dependency;
  - a red commit or a failing gate you cannot fix inside the
    increment;
  - anything touching lib/calc-engine;
  - anything that weakens an evidence property: server-assigned
    timestamps, append-only EntryEvent, immutable firstRecordedAt,
    coordinate rejection.

Phase4parking.md entry format, appended, newest last:
  ## PARK4-<n> - <one-line title>  [FW<task>, <date>]
  QUESTION:  what was unclear, in two sentences.
  TAKEN:     the conservative option, and why it is reversible.
  NOT TAKEN: the alternative, and what it would cost to switch.
  TOUCHES:   files, tests and migrations a switch would change.
  NEEDS:     what the operator must supply to close it.

STANDING PROTOCOL
====================================================================
1. ONE TASK PER PROMPT. Do not start the next.
2. INCREMENTS: implement -> test -> verify -> commit -> push. Green
   after every increment, on the suites the selector chooses
   (R132/R140/R144).
3. COMMIT ONLY ON GREEN, chained with && (R15). A red commit is a
   bounce.
4. COMMITS: "FW<n>: <increment title>"; "chore: <title>" for rulings.
5. SIMPLICITY FIRST. No abstraction before the third use. No ORM
   wrapper over Prisma, no queue abstraction, no admin UI.
6. TEST-FIRST with a RED row per behaviour. R96 codepoint literals,
   R119 singletons by count, R120 fixtures must disagree, R133
   positive signals, R154 mechanisms prove delivery, R180 verify the
   plant.
7. THE API IS THE PRODUCT'S CONTRACT. Every route is /api/v1.
   Tenancy comes from the token, never from a body field. Errors are
   French where a human reads them and stable codes where a client
   does.
8. EVIDENCE PROPERTIES ARE NOT NEGOTIABLE (SPEC 8): the server
   assigns recordedAt and firstRecordedAt; EntryEvent is append-only;
   no payload carrying a coordinate is accepted; ABSENT never reaches
   the engine.
9. QUESTIONS: R156 - park and continue, or stop per its boundary.
10. EXIT ARTIFACT: REPORT-FW<n>.txt, committed and pushed, in the
    report format the task names.

Pure ASCII in prompts and reports. Code carries accented French.
