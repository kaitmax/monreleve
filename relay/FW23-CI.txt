====================================================================
WHY THIS SESSION EXISTS
====================================================================
CI has barely run on this project. Of roughly 120 commits, four jobs
have executed on a runner a handful of times, and three external
checks have NEVER run at all:

  R27's Node parity matrix        never executed (deferred since FW6)
  pnpm test:runtime               unrun FW10 to FW15, rarely since
  the visual suite on a runner    never - it has only run locally

gate:clone (R199) settles the clean-checkout claim on THIS machine.
It cannot settle the different-machine claim: a different CPU
architecture, a different font stack, a different Docker daemon, a
different Node patch release. That is what this window buys.

The repository returns to private afterwards and the R201 budget
split resumes. Leave the workflow in a state where that is ONE
VARIABLE, not a rewrite.

====================================================================
R1 (as reworded by R200). Before starting: pnpm gate:clone green on a
   fresh clone of origin/main's HEAD. Record the commit hash.

reports what it wrote, from its own output.

R212 (new). WHILE THE REPOSITORY IS PUBLIC, WORKFLOW LOGS ARE
   WORLD-READABLE. Before enabling anything: audit every workflow step
   for a command that echoes an environment, prints a connection
   string, dumps a config, or runs with `set -x`. Secrets are masked
   by Actions; DATABASE_URL assembled inline in a step is not a
   secret and will be printed. Report what you found and what you
   changed. If nothing needed changing, say that you looked and where.

R213 (new). AN EXTERNAL CHECK THAT HAS NEVER RUN IS NOT A PASSING
   CHECK. This session's value is the FIRST-EVER result of three
   suites, whatever it is. A failure here is the session succeeding:
   it is a defect that has been latent for three months and is now
   visible. Do not fix a first-ever failure by weakening the check -
   park it (PARK4-<n>) with what it found, unless the fix is
   obviously correct and provable inside this session.

INCREMENT 2 - the first-ever results (R213)
====================================================================
Report each of the three, individually, with its run URL and its
outcome:

  a. NODE PARITY (R27). The formatter suite under Node 22 and 24.
     What this could find: an ICU version difference changing a
     separator codepoint. R6's formatters normalise Intl output
     precisely because ICU has emitted different codepoints across
     versions - this is the check that has been asserting that claim
     without ever testing it on a second runtime.
  b. test:runtime (R81). The refusal behaviour: sitemap 503, health
     degraded, canonicals omitted, /api/ready 503, with
     MONRELEVE_RUNTIME set and the site URL unset.

     rendering, and that failure is INFORMATION, not a problem to
     paper over. R37 already rules that baselines are container-only;
     if the runner's container produces different pixels from the
     local container, the question is WHY - a different base image, a
     different font package, a different device scale factor. Report
     the diff count per file and what the crops show. DO NOT
     regenerate baselines from the runner (R135, R207): the local
     container remains the reference until a ruling says otherwise.
