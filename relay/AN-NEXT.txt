windows had passed, and concluded the phone's clock was "racing" - on
the strength of the session's own sense that only minutes had passed.
An agent cannot feel time pass between commands, and a physical phone
sets its clock from the network. The claim ended the task, so it is
measured before it is believed (R322).

If REPORT-AN-AUTO-2.txt already records this measurement, use its

     adb shell 'cat /proc/uptime; date +%s'
   with the host's own epoch time beside each. Compare the device's

   was not accepted. Explain the "real today row" AN-AUTO-2 recorded and
   its absence later.

INCREMENT 2 - R321: THE DEBUG BUILD REACHES A SERVER FROM A REAL PHONE
====================================================================
The debug build hardcodes 10.0.2.2, which exists only inside the
emulator. On the S9, sessions installed the audit build to reach the
server and then the debug build over it to read the database - it
works, and it is fragile. The debug build accepts the same host
setting the audit build does (-PfrontalierHost with adb reverse), so a
single DEBUGGABLE build reaches the server from a physical phone.
Debug-only cleartext stays limited to 10.0.2.2 and 127.0.0.1; the
release cleartext check must still pass. Prove it: one debug build,
signed in against the container over adb reverse, reading its own
database with run-as. Commit, push.

====================================================================

person opens the app, and an unconfirmed day drifts toward late. FCM

    person to record the day themselves - never a guess.
  - Tapping opens Aujourd'hui. Nothing is recorded from the
    notification itself (D16).
