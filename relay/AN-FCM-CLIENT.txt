R1150. THE DEPENDENCY (authorised by Android Ruling 4, :app ONLY): the Firebase Cloud Messaging
    client - the smallest artefact that receives FCM messages and yields a registration token,
    at a current stable version; name the exact coordinates and version in the report, and the
    APK size delta against AN14a's 12 MB budget (measured on the minified audit/release build).
    NO analytics, NO crash reporting, no other Firebase product, and Firebase's own
    auto-init/analytics collection turned OFF in the manifest. The google-services Gradle plugin
    is NOT required: prefer initialising FirebaseApp from FirebaseOptions whose values come from
    build properties (project id, application id, API key, sender id), so the operator supplies
    them later and NOTHING real is committed. Missing values = push UNAVAILABLE, the app builds
    and runs exactly as today (fail closed for push, open for the app). A placeholder is never a
    plausible-looking key.
R1151. REGISTRATION. When the person is signed in AND has granted notification permission (API
    33+ POST_NOTIFICATIONS) AND push is available, the app POSTs its token to /api/v1/devices
    (read the route's contract - derive, do not transcribe, R181); on token refresh it re-posts;
    on sign-out it does whatever the route/SPEC say about unregistering (read; if nothing exists,
    NOTICED, not invented). Test-first in :app with a fake transport; one R204 test drives the
    real route handler with a token the fake produced.
R1152. RECEIPT. A message from the server's reminder job (read lib/push/message.ts for its exact
    payload) posts the app's EXISTING evening notification surface (reuse the R339 notification:
    same channel, actions, lock-screen privacy - no new copy unless the payload demands it).
    EXACTLY ONE PER DAY (Android Ruling 7): receipt shows nothing if today is already confirmed
    on the phone or a reminder was already shown today; and the auto-mode evening notice
    (SamplingWorker) and the push must not both show for one day - map every path in a table and
    prove the rule with tests on each pair. The table has a SIGNED-OUT row (Android Ruling 8): a
    push arriving while nobody is signed in shows nothing, and the token handling on session end
    attaches to A11's "session ended" seam (REPORT-AN-SESSION-END.txt) rather than a new hook.
R1153. "PUSH AVAILABLE" is ONE named state in :app (token registered and accepted by the server,
    permission granted, Play services present) that A7 will read to decide its 19:00 fallback.
