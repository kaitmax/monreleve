THE TASK
====================================================================
Measured: W10b's gate run 1 ran outside any other load (06:57-07:06Z),
and e2e/rappel-delai.spec.ts failed there twice (lines 45 and 104). The
page state fitted a date filled in before the island hydrated. W11's own
walkthrough met the same thing once. The control repeated one test 160
times in isolation and it passed every time, so the failure is a race
that load exposes.
The orchestrator's read (pointers, not verdicts):
- app/(public)/calculateur-lamal-cmu/DeadlineHelper.tsx holds the date
  in useState('') (about line 68) and renders a CONTROLLED input
  (value={date}, about line 161). A date typed into the server-rendered
  field before hydration is therefore not in state. No deadline is
  computed and no reminder form appears.
- So this is a PRODUCT defect, not only a test race. A person on a slow
  phone who types before hydration gets nothing, and a wait added to the
  spec would hide it.

R1041. THE DEFECT, PROVEN FIRST (R154, R180).
    - A Playwright test HOLDS the helper's JavaScript back: route the
      script requests and release them only after the date is typed.
    - It types a date into the server-rendered field, releases, and
      asserts that the deadline and the reminder form appear.
    - It is RED on your base, with the failure pasted. Holding the
      scripts back is the plant that delays hydration, and it is
      verified to have held something back: say which requests waited,
      and for how long.
