ACCEPTANCE CRITERIA
====================================================================
AC1. POST /api/v1/entries accepts a BATCH and assigns recordedAt and
     firstRecordedAt from the SERVER CLOCK. A payload attempting to
     set either is rejected or ignored - proven, with the server value
     winning. clientClaimedAt is stored verbatim when supplied.
AC2. A payload containing latitude, longitude, accuracy, altitude,
     speed, heading or a provider name is REJECTED with 400. The test
     asserting this is named so it cannot be deleted quietly, and it
     covers nested and unknown-key forms.
AC3. Every write appends an EntryEvent; editing preserves
     firstRecordedAt and detectedKind; a replayed batch carrying a
     seen clientMutationId writes no row and no event and is
     acknowledged, not errored.
