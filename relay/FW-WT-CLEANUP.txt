R1036. THE SCRIPT: web/scripts/wt-cleanup.mjs.
    - It reads `git worktree list --porcelain` of the repository it runs
      in, and considers ONLY worktrees under a root: C:/wt by default,
      `--root <dir>` for the tests.
    - It never treats as a candidate the main checkout, the worktree it
      runs from, or anything outside the root.
    - A directory under the root that is not a registered worktree is
      reported as "not a worktree, left alone", never touched.
    - It fetches origin first (`--no-fetch` for the tests). "Merged"
      means the worktree's HEAD is an ancestor of origin/main.
    - Each worktree gets ONE verdict, with its reason:
      - REMOVE: merged, clean, no lock, no keep marker;
      - REFUSED (lock): a .session-lock.json, whoever wrote it;
      - REFUSED (dirty): `git status --porcelain` is not empty; list the
        paths;
      - REFUSED (unpushed): HEAD is in no remote-tracking ref;
      - KEPT: a `.wt-keep` file, whose content is the reason;
      - SKIPPED (not merged).
    - The DRY RUN is the default. It prints the table with each folder's
      size and the total that `--apply` would free.
    - `--apply` removes exactly the REMOVE rows, with
      `git worktree remove <path>` and NEVER --force, then runs
      `git worktree prune`. It then reads the list again and confirms
      each removed worktree is gone.
    - A REFUSED row is never removed. Its reason is printed, and the exit
      code is non-zero whenever any row was refused (R392's "refuses,
      non-zero, naming the reason"). The other rows are still processed.
    - It never deletes a branch or a remote ref. R392 keeps that for
      after the owning session's report is on main, or the operator's
      word, and it is out of scope here.

R1037. THE TESTS, test-first (R154, R196).

    a temp directory, NEVER under C:/wt, with a bare repository as its
    origin and worktrees in a temp root. One case per verdict:
    - a merged, clean, unlocked worktree: --apply removes it, and it is
      gone afterwards (the positive case);
    - a lock file: refused, still present, exit non-zero;
    - a modified tracked file: refused; an untracked file: refused;
    - an unpushed commit: refused;

    - not merged: skipped;
    - the dry run removes nothing;
