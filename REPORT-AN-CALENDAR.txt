THE DEFECT, from the source. CalendarController.save recorded EVERY slot that had
a kind and always called requestSync; LocalEntryRepository.record always mints a
new id and a new PENDING row; the server's write.ts writes an EntryEvent for every
item it is sent (CREATED or MODIFIED, whatever the value). So an untouched half
became a MODIFIED event - KMP-4's NOTICED 6.

R473 - THE FIX. save() compares each edit with what is stored for its portion -
kind, absence reason and note, every field the sheet edits - and writes only the
portions that differ; a save that changes nothing writes nothing and asks for no
sync (the sheet still closes). The comparison is on what WOULD BE WRITTEN: the
note is normalised blank -> null on both sides, because the sheet seeds an absent
note as "" and "" against null would call an untouched half changed.

THE FOUR TESTS, RED ON MAIN, THEN GREEN (CalendarSaveWritesWhatChangedTest, JVM,
fed exactly what the sheet emits - an untouched note arrives as ""):
