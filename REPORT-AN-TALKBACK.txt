R641 - WHAT WAS SPOKEN, CAPTURED - NOT INFERRED
================================================================================
MECHANISM: Voice Assistant's own VERBOSE log. Each utterance handed to the TTS engine is
logged as
  V/SpeechControllerImpl: Speaking fragment text "<text>" for event <type>
followed by  D/FailoverTextToSpeech: Speak call for talkback_<n> returned 0
and the queue's end by "No next item, stopping speech queue". The reading driver
(evidence/read.mjs) streams `logcat SpeechControllerImpl:V KeyComboManager:D
FailoverTextToSpeech:D *:S`, presses "next", waits until the queue is empty AND 2.5 s of
silence (so a delayed usage hint is caught), and records every utterance per stop with its
event type. Nothing is reconstructed from the node tree.
NAVIGATION - and why it is not a swipe: on Android 10 `input swipe` / `input keyevent` are
injected ABOVE the accessibility input filter and never reach the screen reader (a test
swipe scrolled the launcher to Samsung News instead of moving focus - shots/control1.png);
`sendevent` on /dev/input/event0 is refused by SELinux (Permission denied, enforcing). What
works: Android's own `hid` tool (/system/bin/hid, over /dev/uhid; shell is in group uhid)
registers a virtual USB keyboard, and Alt+Right is Voice Assistant's "navigate next" combo -
logcat confirms each press: "KeyComboManager: matched > keycombo_shortcut_navigate_next".
CONSEQUENCE (recorded, applies to both builds equally): usage hints are the KEYBOARD-mode
wording ("Appuyez sur Alt + ENTER pour activer.") rather than the touch wording.
uiautomator dumps SUSPEND the service while they run (logged "... est desactivee"), so no dump
is ever taken during a reading; states are set up with the service off, then each reading
enables it, force-stops and relaunches the app (stop 0 = what is spoken on launch), and reads
from the first "next".
REPEATABILITY CONTROL: the same state on the same build read twice is IDENTICAL (W0 base:
two runs; H1 head: two runs).
COMPARATOR CONTROL: evidence/cmp.mjs compares the stops line by line (text + event type +
hints). Pointed at two different states (W0-head vs H0-head) it reports 50 differing stops,
so "IDENTICAL" below is a result it can fail to give.
