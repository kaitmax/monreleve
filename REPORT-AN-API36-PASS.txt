WHAT GOOGLE PLAY REQUIRES OF compileSdk (read 2026-11-19)
  - developer.android.com/google/play/requirements/target-sdk: "Starting August 31 2026: New apps
    and app updates must target Android 16 (API level 36) or higher to be submitted to Google
    Play". Extension to November 1, 2026 on request. The page states requirements on
    targetSdkVersion only.
  - support.google.com/googleplay/android-developer/answer/11926878 (Target API level
    requirements): "When you publish a new app, you must target Android 16 (API level 36) or
    higher." No mention of compileSdk.
  - developer.android.com/about/versions/16/setup-sdk: compileSdk 36 "To access Android 16 APIs";
    targetSdk 36 "Once you're ready to opt in to the new runtime behaviours"; AGP >= 8.9.0-rc01
    for the Android 16 SDK (ours: 8.10.1). Two independent settings; no stated constraint
    between them on that page.
  - So: NO compileSdk REQUIREMENT IS STATED by Play (read 2026-11-19). That is not the same as
    "compileSdk 35 + targetSdk 36 is accepted at upload": only an upload proves acceptance, and
    the upload is the operator's (AN14b). The BUILT release APK already declares
    targetSdkVersion 36 (PARKAN-33, aapt2 badging), which is the field Play reads.
  - Secondary sources (Flutter's contributor doc, a mailing-list thread, via web search) state
    compileSdk >= targetSdk as a convention; AN14a measured AGP 8.10.1 building 35/36 with no
    error and no warning. Not a Play rule.

DEFECTS FOUND
D1 (FIXED in :app, R1082 - see FIX below): UrlConnectionTransport.executeForBytes - the bytes path
   used by the PDF/CSV exports - had no IOException -> TransportException translation, unlike
   execute (R386). AuthApi.authenticatedGetBytes catches TransportException only (R387), so any
   network failure during an export escaped to Dispatchers.Main and killed the app. Reproduced
   twice on the emulator API 36: a cold server render (14 993 ms > 15 000 ms read timeout ->
   SocketTimeoutException) and airplane mode (ConnectException). Not API-36-specific: any
   Android version, any network failure during an export. The iOS twin is NOT affected:
   NsUrlSessionTransport.executeForBytes goes through the same perform() that wraps every failure
   in TransportException (read only, shared/src/iosMain/.../NsUrlSessionTransport.kt:78-102).
