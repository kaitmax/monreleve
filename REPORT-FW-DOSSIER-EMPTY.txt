route ALREADY answers 200 with the same envelope: zero days counted,

payload states (tiles.workedDays: 240 for a whole year, 80 for Camille's 2024

says: say what the existing contract and the engines return for "no
denominator"; if they define nothing, STOP and ask. They define nothing:
  - the web engine REFUSES (validate.ts: PERIOD_OUT_OF_RANGE,

    ValidationError.PeriodOutOfRange; Validate.kt);
  - docs/api-v1.md 8.1 types every rate as a number; there is no null, no flag,
    no "undefined" form anywhere in the contract.
STOPPED. No code was written for it. The question, with what each answer costs,
is QUESTIONS Q1; the register entry is PARK-H1.

R549 - A REPLAY IS MEASURED, AND NOTHING ELSE CHANGES
--------------------------------------------------------------------------------
THE CHANGE (web/lib/auth/tokens.ts, commit b757d2e). In rotateRefreshToken's
replay branch - `if (row.consumedAt !== null)` - AFTER
revokeSession(row.sessionId, 'TOKEN_REPLAYED'), logReplayDelta(row.consumedAt)
writes exactly:

    [auth] refresh replay delta_seconds=<N>

  N = Math.floor((Date.now() - consumedAt) / 1000): whole seconds ELAPSED, raw
  (a clock that moved backwards shows as negative rather than being tidied).
  The prefix is the exported constant REPLAY_DELTA_LOG_PREFIX, which the test
  reads (R181). console.warn - the '[auth] ...' shape the server uses, at the
  level the server uses for operational facts that are not errors ('[export]
  pdf busy'); in Node both warn and error go to stderr (DEVIATION 4). Wrapped in
  try/catch and run after the refusal, so a failing sink cannot turn a refusal
  into a 500. NO identifier of any kind; no schema change - consumedAt already
