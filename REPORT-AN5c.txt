THE INJECTION (R284, increment 1, commit 60306fa)
--------------------------------------------------------------------------------
HOW THE SESSION IS OBTAINED. android/scripts/an5c-signedin.mjs plants a hashed
sha256 VerificationToken in a scratch database and exchanges it at the real
GET /api/v1/auth/callback for the token pair {accessToken, refreshToken,
accessExpiresAt, refreshExpiresAt} -- the same recipe AN5b's AC2 run used. The
four fields are passed to a DEBUG-ONLY SessionInjectionActivity as intent extras:
  adb shell am start -n ch.monreleve.app/ch.monreleve.app.debug.SessionInjectionActivity
    --es accessToken <jwt> --es refreshToken <opaque> --es accessExpiresAt <iso>
    --es refreshExpiresAt <iso> [--es canton GE --es employmentRate 100 ...]
The activity validates, stores via KeystoreTokenStore.save() (synchronous
commit()), and optionally seeds settings via SharedPrefsSettingsStore. The
walkthrough force-stops and relaunches MainActivity, which re-reads a durable
session in onCreate. No typing -- the adb text that broke AN5b twice is gone. The
downstream screens still call the REAL server at 10.0.2.2:3000.

THE THREE GUARDS, each proven with a planted violation (R178/R180), then reverted:

  (a) the receiver exists ONLY in the debug source set.
      NoDebugInjectionInMainTest scans src/main + src/release for the marker.
      PLANT: a SessionInjectionLeakPlant.kt placed in src/main ->
        theInjectionExistsOnlyInTheDebugSourceSet FAILED.
      (Copying the exact class instead REDECLARES and fails to compile -- a
      second, incidental barrier, recorded so the plant's shape is honest.)

  (b) the MERGED RELEASE MANIFEST is free of it (exactly as AN4's
      checkReleaseCleartext, dependsOn processReleaseManifest, stripComments).
      PLANT: declared the activity in src/main/AndroidManifest.xml ->
        checkReleaseNoDebugInjection FAILED - "the debug session injection
        ('SessionInjection') is present in the merged RELEASE manifest".
      Distinct from (a): no .kt in main, so (a) stays green on this plant.

  (c) the intent accepts ONLY a well-formed session and refuses anything else BY
      NAME (R198). SessionInjectionTest (in src/testDebug, so testReleaseUnitTest
      never compiles against the debug class).
      PLANT: weakened the validator to accept a blank token (isNullOrBlank ->
        == null) -> "a blank refresh token is refused by name" FAILED.
      Every refusal names the FIELD, never a value (a value could be a token; the
      log fence forbids logging a credential).

R241 BOUNDARY CHECK: no path lets the injection reach a release build. The class
and the manifest entry live only in src/debug; guards (a) and (b) fail if either
appears in a shipped source set or the merged release manifest. Both proven.
