R765 - FOR THE PILOT (IOS-1b-B)
================================================================================
CAUSE: NOT platform-specific. It is shared code reading a load as a transition: the first
frame (no entries) then the rows makes the afternoon heading APPEAR as a polite live region
and requests focus on it. Android's accessibility layer announced that on Compose 1.7.0
(2458dbe) and 1.7.6 alike, so - unlike R700 - no library version was needed to trigger it.
On iOS the same composables run through Compose Multiplatform 1.7.3's UIKit bridge; whether
VoiceOver announces an appearing live region, and whether a Compose focus request moves the
VoiceOver cursor, are IOS-1b-B's to hear. Because it does not depend on a library quirk,
VoiceOver is MORE likely to share it than it was R700.
FIX: in commonMain (HalfDayChoiceCard.kt), so the iOS build carries it. No iOS test was
added: the pilot has no morning-only scenario (adding one is fixture scope), and the one
iOS run's job is to prove that :shared builds and its existing tests stay green.
CHECK ON VOICEOVER: (1) open the pilot on a day whose MORNING only is answered (needs such a
scenario, or a morning tapped then the app relaunched) - nothing about "Apres-midi" should
be spoken before the first swipe, and the cursor should not jump to it; (2) on a fresh
half-day, tap a morning answer - "Matin enregistre. Apres-midi : a renseigner." should be
announced; (3) swipe to the afternoon heading - it still reads that sentence.
