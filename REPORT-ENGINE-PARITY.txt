DEVIATIONS
====================================================================
1. @Suppress("UnusedParameter") on missionCapFor. The web keeps `method` in the
   signature (TypeScript tolerates an unused param); Kotlin detekt's
   UnusedParameter flags it. To keep the signature identical to web and leave
   both call sites unchanged ("the SAME correction, nothing more"), the param is
   kept and suppressed with an inline reason - the codebase's established pattern
   (many @Suppress("...") with reasons). The alternative (removing `method`) would
   ripple through two production call sites and every test call and diverge from
   the web signature.

2. R348 scope is per-file's-consumers, NOT the literal "both engines, every file".
   The prompt says "fails if either engine's suite does not consume it", which
   read literally means both engines must consume every fixture file. That is
   infeasible without either porting web forecast (far out of scope) or hand-
   excluding forecast-cases.json (a list, which R246 forbids). The implemented
   rule - every section consumed by every engine that READS the file, plus every
   file read by >=1 engine - is green on the current tree, catches the mission-cap
   class (a shared section read by one engine and not the other, which is exactly
   what REG-APPLY almost shipped), makes the required plants fail by name, and
   keeps forecast-cases.json VISIBLE (printed as single-engine) rather than
   silent. Tightening to "both engines, always" is a one-line change once the web
   forecast consumer (FW-FORECAST) exists. Recorded here per R156 (conservative,
   reversible) because no advisor was available this session.

3. The on-device UI leg of the live check was bounded (see THE LIVE CHECK).
