DEVIATIONS
================================================================================
1. THE PREP PASS (above): one unmeasured sign-in + onboarding + sign-out on main's build, so
   "signed in" is the same screen on both measured runs. Without it the first build would land
   on onboarding and the second on the shell - a difference of state, not of code.
2. RUN 1 OF MAIN WAS ABORTED AND REDONE IN FULL. Two harness defects, both mine:
   (a) read.mjs's default end pattern "^Retour, Touche" (meant for the navigation bar) matched
       the request screen's own back button, "Retour, Touche, Mon Releve", so both request
       readings ended at stop 1;
   (b) the Parametres scroll (six swipes to the end) left "Se deconnecter" off screen, and the
       script aborted on its own check.
   Fixed in flow.sh (end pattern "dernier element|Applis recentes|Applications recentes|Barre de
   navigation", ASCII dots for the accents; to-the-end then two slow drags back). Run 1 then
   signed out by hand (unmeasured) and its files were moved, kept, to run1-aborted/. Main was
   then run again from the start, and the tip once, with the same script. No state of run 2 or
   of the tip was re-read.
3. read.mjs's loop guard raised 4 -> 8 (it ends a reading when one focus text repeats more than
   N times; the six code boxes after a wrong code each speak "0, Zone d'edition", so run 1's
   wrong-code reading stopped at box 5). Edited at ~09:27 (phone clock) during run 2 of main, at about
   the moment its welcome reading began (first utterance 09:27:39) and before every later one;
   welcome has no repeated stop, and the guard can only change where a reading ends, and no other state repeats a stop more than four times. Both builds' readings
   used 8 for every state that has repeats.
4. The wrong code is the fixed 000000, and the reader spoke its six "0" boxes; it is not a
   sign-in code. The real codes were never printed, captured or spoken (typed into the boxes
   only; the right code's state is not read - the screen leaves at once).
5. shot.mjs gained one refusal: it writes nothing unless the EditText count found equals the one
   expected for the state (R574: a dump that misses a field must not produce an unmasked file).
   Never triggered.
6. dev.log holds the sign-in links and codes; it stays in the untracked evidence folder and was
   only ever read through filters (statuses) and getcode.mjs.
