Changed: web/lib/ui/core/styles/tokens.scss.

The token --radius-checkbox: 6px already existed from FW1; what R4 changes is
that 6 is part of the permitted set rather than an anomaly awaiting a ruling.
Its comment no longer says "outside the closed radius set", and the radius
section header now reads {4, 6, 8, 12, 14, 16, 20, 24, 999}.

Enforcing that required a different rule, and this is the one real design
decision in increment 0. FW1 fenced radius with
scale-unlimited/declaration-strict-value, which rejects any raw value
outright - so it rejected 6px exactly as readily as 7px and could not express
a closed set at all. R4 asks for an allow-list that reads as the set, and 0c
asks for 6px accepted and 7px rejected. Radius therefore moved to
declaration-property-value-allowed-list. The config also moved from JSON to
.stylelintrc.mjs so the set is written once as an array rather than buried in
a regex. See DEVIATION 8: this accepts a raw radius drawn from the set, which
is looser than FW1's token-only fence in that one respect and stricter in
another - the set itself is now enforced, which token-only never did.

DECISION
--------
GO.

  representative page, Gate A (total <= 125.0):  103.1, 21.9 KiB spare
  representative page, Gate B (delta <= 25.0):     2.5, 22.5 KiB spare

Both gates pass with the representative set in place. pnpm size is green. No
escalation, and no gate value was touched.

The reason to be confident is the ratio rather than the margin. Our own
component vocabulary - Sass tokens, CSS Modules, lucide-react, Inter variable,
one interactive island - costs about 2.5 KiB gzip. The framework floor costs
100.6 KiB. About 97.6 per cent of a public route's first-load JS is Next and
React, and essentially none of it is ours. The risk this spike was scheduled
to find - that our component choices would blow the budget - is not present.

What the remaining 22.5 KiB still has to cover:

  FW3-FW5   lib/calc-engine, pure TS, zero runtime deps   single-digit KiB
  FW6-FW7   zones, French formatters, renderRailSvg       small; Intl is
                                                          a platform API
  FW8-FW9   the real components replacing this markup     about 2.5 KiB, on
                                                          the evidence here
  FW13      URL params codec                              under 1 KiB
  FW15      JSON-LD, Umami (same-origin script)           no first-load JS

The engine is the only unknown of any size and it is pure TypeScript with no
dependencies by spec. A calculator route landing around 108-112 KiB total is
the realistic expectation, well inside Gate A.

What this spike does NOT prove:
  - LCP. Gate A is a byte budget. The 2.5 s slow-4G requirement is a separate
    Lighthouse gate that tightens at FW11.
  - Behaviour. The island was built to be weighed. It has no tests beyond the
    build's own prerender, and it is not what FW8-FW9 will ship.
  - Multiple islands. One island per route was measured. Three independent
    islands on a route pay more boundary overhead, though not more React.
