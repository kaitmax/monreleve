R1151 - REGISTRATION
====================================================================
Contract read from docs/api-v1.md section 10 and web/app/api/v1/devices/route.ts (not retyped):
POST { fcmToken, platform?, appVersion? }, idempotent per token, reassigned to the caller, "made after
sign-in and on every launch afterwards"; no DELETE ("signing out revokes the session; the token is
pruned when the service reports it dead").
The pass (PushSync.sync, PushRegistration.kt):
  signed out -> SIGNED_OUT, nothing sent;
  not configured -> NOT_CONFIGURED, nothing sent, Play services never consulted, no token asked;
  no Play services -> NO_PLAY_SERVICES; no permission -> NO_PERMISSION;
  no token -> NO_TOKEN; non-2xx or unreachable -> REGISTRATION_REFUSED (R1191: an Ok is not acceptance);
  2xx -> registered; then reminderEnabled is written TRUE when opted in and the server does not
  already hold it from this phone, FALSE only when this phone turned it on and the person opted out
  or push became impossible here; a transient failure leaves the server's value alone.
Triggers: MainActivity's signed-in shell LaunchedEffect (keys: the evening opt-in and the alert
opt-in, so a fresh POST_NOTIFICATIONS grant registers at once), and MonRelevePushService.onNewToken.
Body: { fcmToken, appVersion } - NO `platform`: the route answers 400 coordinates_refused to it
(web/lib/entries/no-coordinates.ts substring-matches `lat`). Pinned in push-client-join.test.ts.
Sign-out: route/SPEC have no unregister; the client invalidates its own token
(FirebaseMessaging.deleteToken, fire-and-forget) so the server's next send answers 404 and prunes the
row (api-v1 10.4's own mechanism). NOTICED: no server-side unregister exists.
TEST-FIRST: stubs first, then app/src/test/kotlin/ch/monreleve/app/push/{PushSyncTest (16),
PushClientFixtureTest (4), PushConfigTest (4), PushReceiptTest (12)} and SessionEndSeamTest (+2, 3
assertions added): RED 25 of 72 by assertion (evidence red-1-push-and-seam.log), then GREEN.
PushSyncTest runs the pass over the REAL SessionManager and AuthApi with only the HTTP transport faked.
R204: web/tests/db/push-client-join.test.ts, against the scratch DB, 4 passed: the fixture's token
posted to the REAL POST route (200, token not echoed), the fixture's opt-in to the REAL PATCH /me,
runDailyReminders at the fixture's 17:31 Paris -> FakePushSender delivered exactly that token with
