THE PLANTED CODE. A seventh member added to the engine's ValidationError
union, with no copy written for it:

  lib/fr/errors.ts(65,14): error TS2741: Property 'PLANTED_FOR_AC1' is missing
    in type '{ RATE_OUT_OF_RANGE: string; ... }' but required in type
    'Record<"RATE_OUT_OF_RANGE" | ... | "PLANTED_FOR_AC1", string>'.
  lib/fr/errors.ts(112,13): error TS2322: Type '{ readonly code:
    "PLANTED_FOR_AC1"; }' is not assignable to type 'never'.

Two failures from one plant, by design: ERROR_COPY is Record<Code, string>, so
a missing key and an extra key are both errors, and errorMessage's switch ends
in a `never` assignment as an independent second guard.

THE PART WORTH RECORDING. With the code planted, the unit suite stayed GREEN
at 11 passed. AC1 says "adding a code without copy fails CI" - it does, but it
fails at `pnpm typecheck`, not at `pnpm test`. A pipeline that ran only the
tests would ship a form that renders an empty error and blocks the user with
no explanation. CI runs typecheck first, so the criterion holds; the mechanism
is not the one a reader would assume.

A COMMENT CORRECTED RATHER THAN LEFT TO MISLEAD. The test file originally
claimed its CODES array was a second compile-time guard. It is not:
`readonly Code[]` accepts a SUBSET, so an added code compiles fine and only a
removed or renamed one fails. What actually guards it is the runtime
comparison against ERROR_COPY's keys - verified by dropping a code from the
array and watching that test fail. The comment now says which is which.

Removed; clean run: 11 passed.

DEVIATIONS
================================================================================

1. FIELDGROUP TAKES A FUNCTION AS children. The prompt says "the control slot
   (children - composition, not a props bag)". A plain slot cannot be wired:
   FieldGroup would have to reach into an element it does not own via
   cloneElement and assume the child accepts aria-describedby, which is
   untypeable and silently wrong for a fragment or a wrapped child. A props
   bag would fix the control to <input>. Documenting the contract would make
   the guarantee a convention, which is what the component exists to replace.
   The function hands the caller exactly the attributes the control must
   carry - props going TO the caller rather than coming from it, which is the
   direction that makes them provable. Every test asserts on the real <input>
   the caller rendered.

   Six of those tests failed on their first run against a component the markup
   dump proved CORRECT. Testing Library registers its own afterEach cleanup
   only when a global afterEach exists, which needs vitest globals: true - not
   set in this repo, on purpose. Without an explicit afterEach(cleanup) every
   render accumulates in one jsdom document and screen queries search a page
   holding several copies. The same fix was applied to FW8's axe sweep, where
   all eighteen states were accumulating: it passed either way, but the rules
   axe evaluates against the DOCUMENT rather than the container - duplicate
   ids above all - were being asked about a page that never exists.

2. TWO DATAGRID TESTS WOULD HAVE PASSED FOR THE WRONG REASON, same cause.
   Testing Library's default normaliser collapses whitespace, and U+202F - the
   narrow no-break space formatDays uses as a group separator - is whitespace
   to that regex. So getByText(formatDays(1247)) searches for "1<U+202F>247"
   while the DOM text has been normalised to "1 247" with an ordinary space.

   One failed loudly against a correct table, and a codepoint dump showed the
   cell was exactly right - 31 202f 32 34 37 on both sides. The worse half was
   GREEN: "the total row is absent unless given" used queryByText for the same
   string and expected null, which it would return whether or not a footer
   existed. Both now read textContent, which is stricter than the query helper
   rather than looser - had the first matched, it would have matched EITHER
   separator, hiding the exact thing SPEC 19 pins.

3. THE ERROR MESSAGE IS text-primary AND THE ICON CARRIES THE COLOUR. The
   prompt already asks for this ("a 13 px error message in text-primary with a
   Lucide circle-alert 16 in the error colour"); recorded only because it is
   the same split R57 made for the ZoneBadge chip, and the consistency is
   deliberate rather than coincidental.

4. .u-visually-hidden ADDED TO global.scss, joining .u-tnum. Needed by
   DataGrid's caption and by PublicShell. Its three 1 px values are EXEMPTED
   from the token rule with a stylelint disable and a reason at the line,
   rather than tokenised: they are the mechanics of a known idiom - the
   element must stay rendered and non-empty to remain in the accessibility
   tree - and a --size-visually-hidden token would put a number in the design
   system that no designer chose and no design could change.

5. THE FD BRIEFS ARE AT THE REPOSITORY ROOT, not at prompts/design-frontier/
   where the FW9 prompt says to read them. FD1, FD11, FD12 and FD13 exist;
   FD2 does not. Found by looking, since the prompt's path returns nothing.
   Recorded because a future prompt using the same path will find nothing and
   may conclude the briefs do not exist.

6. THE CONTRAST AUDIT'S COMPONENT LIST NOW READS THE DIRECTORY. It named five
   components by hand, and FW9 adds four - the same shape of staleness as the
   audit's original token-without-size bug, one level up. It picked up

   it cannot silently become empty.

7. pnpm test:a11y WAS ADDED IN FW8 and is used here. Noted because the FW9
